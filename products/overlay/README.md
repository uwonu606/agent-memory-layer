# 얹는 제품

Claude Code의 auto memory를 켠 채 두고, 그 위에 장치를 하나씩 얹어 기억이 실리고 바뀌는 일을 사람이 읽어서 알게 하는 제품이다. 기억을 쓰고 싣고 고치는 일은 기준선(auto memory)이 그대로 하고, 이 제품은 보이고, 기록에 남기고, 되돌리게 하고, 고칠 때 놓친 기억을 모델에게 알린다.

얹는 제품을 쓰는 사람과, 이 폴더의 코드를 이어서 고칠 사람이 읽는 글이다. 이 글에서 기록, 판, 실림은 이 저장소의 문서가 아니라 제품 안의 것을 가리킨다. 기록은 제품이 기억 폴더 밖에 덧붙여 남기는 층이고, 판은 기억 파일 하나의 한때 모습이다. 낱말의 뜻은 [용어집](../../GLOSSARY.md)에 있다.

## 장치

장치는 [판단과 방향](../../docs/direction.md)의 제품의 차례대로 하나씩 얹는다. 이 폴더에 있는 것은 둘째, 셋째, 넷째다.

| 차례 | 장치 | 붙는 곳 | 이 폴더의 파일 |
|---|---|---|---|
| 1 | 모든 저장소의 기억을 폴더 하나에 둔다 | user settings의 `autoMemoryDirectory` 한 줄 | 없다 |
| 2 | 실린 기억을 사람 화면에 보이고, 기억이 실리고 바뀐 일과 그때의 판을 기록에 남기고, 판으로 되돌린다 | user settings의 hook 둘(`SessionStart`, `Stop`) | 아래 [파일](#파일)의 코드 전부 |
| 3 | 기억마다 남긴 저장소와 어디서나 쓰이는지를 적게 하고, 그 작업에서만 한 말은 기억으로 쓰지 않게 한다 | 모델이 읽는 지시 파일에 더하는 글 | [memory-rules.md](memory-rules.md) |
| 4 | 기억이 바뀐 답이 끝날 때, 바뀐 기억의 옛 값을 글자 그대로 품은 다른 기억을 찾아 모델에게 알린다 | 둘째 장치의 `Stop` hook 명령에 붙이는 인자 `--find-old-values` | `old_values.py` |

둘째 장치는 셋째, 넷째 장치 없이도 돈다. 셋째 장치가 붙어 있으면 색인 줄의 `[scope]`를 사람 화면에 함께 보인다. 넷째 장치는 둘째 장치의 `Stop` hook 안에서 돌아서, 둘째 장치 없이 붙지 않는다.

## 둘째 장치가 푸는 것

> **예시** — `todo-app` 저장소에서 세션을 열고 "커밋은 이제 기능 하나에 하나다, 고쳐"라고 한다. 모델은 기억 파일 `commit-unit.md`를 고친다.

기준선만으로는 아래 넷을 읽어서 알 수 없다([원래 auto memory의 동작](../../docs/claude-code/auto-memory.md)의 사람에게 보이지 않는 것). 이 장치를 붙이면 예시의 세션에서 각각 아래처럼 보인다.

| 알 수 없던 것 | 이 장치에서 |
|---|---|
| 세션이 시작할 때 어떤 기억이 실렸나 | 첫 화면에 실린 기억의 개수와 기억마다 한 줄이 뜬다. 색인이 잘렸으면 몇 줄 가운데 몇 줄이 실렸는지 뜬다 |
| 기억 하나가 언제 어느 세션에 실렸나 | 기록 폴더의 `history/commit-unit.md`의 실린 때에 있다 |
| 처음 언제 남았고 언제 고쳐졌나 | 같은 파일의 바뀐 차례에 있다. 모델이 파일을 지우고 새 이름으로 다시 써도 옛 파일의 내력은 남는다 |
| 무엇에서 무엇으로, 어떤 말 때문에 바뀌었나 | 같은 파일에 바뀐 줄과 그 답을 시킨 사람의 말이 있다. 답이 끝날 때 화면에 한 줄이 뜨고, 그 줄의 명령으로 바뀌기 전의 판으로 되돌린다 |

둘째 장치는 모델에게 가는 글을 하나도 더하지 않는다. hook은 사람 화면에 `systemMessage`만 낸다. 모델에게 가는 글을 더하는 장치는 넷째뿐이고, 그 글은 옛 값을 품은 다른 기억을 찾은 답에서만 `Stop` hook의 `additionalContext`로 나간다.

## 넷째 장치가 푸는 것

> **예시** — 기억 `redis-port.md`가 "Redis 포트는 6380이다"이고, `local-stack.md`가 "로컬 스택을 띄우면 캐시는 6380에서 듣는다"이다. 사람이 "Redis 포트를 6390으로 바꿨어, 기억 고쳐"라고 한다. 모델은 `redis-port.md`만 "Redis 포트는 6390이다(6380에서 바뀜)"로 고치고 답을 끝낸다.

기준선은 사람의 말에 든 낱말로 기억 폴더를 찾아 고친다. 같은 값이 다른 낱말로 적힌 기억은 놓치고([원래 auto memory의 동작](../../docs/claude-code/auto-memory.md)의 2.1.332에서 다시 본 것), 놓친 기억의 옛 값은 다음 세션에 지금 값처럼 실린다. 이 장치를 붙이면 예시의 답이 끝날 때 장치가 `6380`이 `local-stack.md`에도 있는 것을 찾아 모델에게 알리고, 모델은 같은 답을 이어서 `local-stack.md`를 고치거나 다른 사실이면 그대로 둔다. 찾는 일은 코드가 하고, 같은 사실인지 가려 고치는 일은 모델이 한다.

모델에게는 아래 글이 `additionalContext`로 간다. 지시가 아니라 사실로 적는다.

```text
기억 도구가 이번 답에서 바뀐 기억의 옛 값을 다른 기억에서 글자 그대로 찾았다. 찾은 기억은 이번 답에서 바뀌지 않았다.
옛 값 `6380` (redis-port.md에서 바뀜)
- local-stack.md: 로컬 스택을 띄우면 캐시는 6380에서 듣는다.
이 줄이 바뀐 값과 같은 사실을 적었다면 옛 값이 남아 있는 것이고, 다른 사실을 적었다면 그대로 맞다.
```

사람 화면에는 둘째 장치의 줄 아래에 한 줄이 더 뜬다. 대화형 화면에는 모델에게 간 위 글도 `Stop hook says:` 아래에 그대로 보인다. 모델이 이어서 고친 기억은 다음 `Stop`에서 둘째 장치의 줄로 뜨고, 그 답에서는 넷째 장치가 다시 알리지 않는다.

```text
이번 답에서 기억 1개가 바뀌었다: redis-port.md 고침. 되돌리기: python3 /path/to/agent-memory-layer/products/overlay/restore.py redis-port.md 1
옛 값을 품은 다른 기억 1개를 모델에게 알렸다: local-stack.md (6380).
```

### 옛 값

| 낱말 | 이 장치에서 |
|---|---|
| 값 | 줄 하나에서 글자 그대로 옮겨 적은 것. backtick으로 감싼 글 전체이거나, ASCII 글자·숫자와 `. _ / : @ ~ + -`가 이어진 덩어리 가운데 숫자나 `/ _ . @ : -`를 품은 것이다. 덩어리를 `:`, `/`, `@`에서 나눈 조각도 따로 본다(`localhost:6380`의 `6380`, `react@18.3.1`의 `18.3.1`). 두 글자보다 짧으면 값이 아니다. backtick 밖의 한글 낱말과 영문 낱말(`Redis`, `uv`)은 값이 아니다 |
| 사실 글 | 기억에서 사실을 적은 글. frontmatter의 `description` 값, 본문의 줄, 색인 줄의 설명(`[scope]` 뒤의 글)이다. 기억의 구조가 싣는 글자는 뺀다. frontmatter의 다른 칸(`name`, `repo`, 시각, 세션 id), 색인 줄의 제목과 링크 대상과 `[scope]`, 본문의 `[[이름]]` 링크와 다른 기억 파일을 가리키는 링크 대상(`[글](local-stack.md)`의 `local-stack.md`)이 그것이다. 옛 값을 뽑을 때와 찾을 때 모두 사실 글만 본다 |
| 옛 값 | 이번 답에서 바뀐 기억의 앞 판과 뒤 판의 사실 글을 줄로 견준다. `description`, 본문, 색인 줄의 설명은 따로따로 견준다. 바뀐 덩어리(hunk)마다, 뒤쪽 줄에 앞쪽 줄에 없던 값이 생겼을 때만 본다. 그때 앞쪽 줄의 값 가운데 뒤쪽 줄에서 사라진 값이 옛 값이다. 사라진 값이 없으면, 곧 옛 값을 내력으로 남긴 고침이면, 앞쪽 줄의 값이 모두 옛 값이다 |
| 지우고 새 이름으로 다시 쓴 기억 | 이번 답에서 지워진 기억마다, 그 마지막 판을 앞 판으로, 이번 답에서 새로 생긴 기억을 모두 이은 글을 뒤 판으로 본다 |
| 품었다 | 옛 값이 다른 기억의 줄에 나오되 앞뒤가 ASCII 글자·숫자·`_`에 붙지 않고, 이음 글자(`. _ / : @ ~ + -`)를 건너 그런 글자에 이어지지도 않는 것. 한글은 붙어도 된다. `6380에서`는 `6380`을 품고, `16380`, `6380.1`, `v6380`은 품지 않는다 |
| 찾는 곳 | 이번 답에서 바뀌지도 새로 생기지도 않은 기억의 사실 글. 알림에는 그 사실 글이 든 줄을 파일에 적힌 그대로 보인다 |

알림 하나에는 찾은 줄을 10개까지 담고, 넘친 줄은 개수만 적는다.

이 정의가 놓치는 것이다.

- backtick 밖의 이름이 바뀐 고침. "pnpm을 쓴다"가 "uv를 쓴다"로 바뀌면 값이 없어서 찾지 않는다.
- 한 글자 값. "2주"가 "3주"로 바뀐 것.
- 새 값 없이 값을 지우기만 한 고침과, 다시 쓰지 않고 지우기만 한 기억.
- 사실 글 밖에서만 값이 바뀐 고침. 색인 줄의 제목이나 frontmatter의 `name`에만 있던 값이다. 바뀐 기억 자신의 색인 줄이 바뀌지 않고 옛 값을 품은 채 남은 것도 놓친다.
- 같은 사실을 다른 글자로 적은 기억(`6380`과 "육삼팔공"), 그리고 값이 없는 규칙.
- `stop_hook_active`가 참인 답에서 바뀐 값. 다른 `Stop` hook 때문에 이어진 답도 여기에 든다.
- 세션이 시작할 때 세션 밖의 바뀜으로 잡힌 고침. 넷째 장치는 `Stop`에서만 돈다.
- 모델이 아무 기억도 고치지 않은 답. 사람이 부른 이름이 기억에 적힌 이름과 달라서 모델이 고치기 전에 어느 기억인지 되묻는 경우다. 바뀐 기억이 없으면 옛 값도 없다.

이 정의가 잘못 알리는 것이다. 모두 모델이 읽고 그대로 두면 되는 알림이지만 답을 하나 더 돌게 한다.

- 같은 값을 다른 사실에 쓰는 기억. 다른 서비스의 포트가 같은 `6380`인 경우다.
- 한 줄에 값을 덧붙이기만 한 고침. "6380이다"가 "6380이다. 비밀번호는 `REDIS_PW`에 있다"가 되면 `6380`을 옛 값으로 본다. 글자만으로는 옛 값을 내력으로 남긴 고침과 가르지 못한다.
- 옛 값을 내력으로 남기며 한 덩어리의 값 하나만 바꾼 고침. "Redis는 6380, Postgres는 5432"를 "Redis는 6390(6380에서 바뀜), Postgres는 5432"로 고치면 `5432`도 옛 값이 된다. 내력 없이 바꾸면 `6380`만 옛 값이다.
- 한 답에서 서로 관계없는 기억 하나를 지우고 다른 기억을 새로 쓴 것. 지운 기억의 값이 옛 값이 된다.
- 사실 글 안에서 다른 기억의 파일 이름을 링크 없이 맨 글자로 적은 것. `redis-port.md`가 옛 값이 되면 본문에 `redis-port.md`라고 적은 다른 기억을 알린다.
- `20`처럼 짧은 숫자가 다른 뜻으로 쓰인 줄.

## 붙이는 법

1. [settings.example.json](settings.example.json)의 `hooks`를 user settings(`~/.claude/settings.json`)에 더한다. `/path/to/agent-memory-layer`는 이 저장소를 내려받은 절대 경로로 바꾼다. 이미 `hooks`가 있으면 `SessionStart`와 `Stop`의 배열에 한 칸씩 더한다. `Stop` 명령 끝의 `--find-old-values`가 넷째 장치를 켠다. 이 인자를 빼면 넷째 장치만 떨어지고, 출력과 기록은 둘째 장치만 있을 때와 글자까지 같다.
2. 첫째 장치를 함께 쓰려면 같은 파일에 `"autoMemoryDirectory": "~/agent-memory"` 같은 한 줄을 둔다. 없으면 저장소마다의 기본 기억 폴더를 따른다.
3. 새 세션을 연다. 첫 세션에서는 이미 쌓인 기억이 모두 세션 밖에서 생긴 것으로 기록에 들어간다. 기억 파일은 바꾸지 않는다.

모두 떼려면 settings에서 그 두 칸을 지운다. 기록 폴더는 남는다.

Python 3.10 이상과 표준 라이브러리만 쓴다(돌려 본 것은 3.14다). 기록 폴더를 잠글 때 `fcntl`을 써서 Linux와 macOS에서만 돈다.

## 사람 화면

세션이 시작할 때 뜨는 글이다. 기억 줄은 10개까지 보이고, 넘치면 나머지 개수와 전체 목록 파일의 경로를 보인다.

```text
기억 200개가 실렸다. 색인 250줄 가운데 앞 200줄만 실렸다.
- 커밋 단위 [todo-app]
- uv를 쓴다 [everywhere]
  … (10줄까지)
- 그 밖에 190개. 전체 목록: <기록 폴더>/loads/<세션 id>.md
세션 밖에서 바뀐 기억 2개를 기록에 남겼다. 내력: <기록 폴더>/history
```

답이 끝날 때, 그 답에서 바뀐 기억이 있을 때만 한 줄이 뜬다.

```text
이번 답에서 기억 1개가 바뀌었다: commit-unit.md 고침. 되돌리기: python3 /path/to/agent-memory-layer/products/overlay/restore.py commit-unit.md 1
```

넷째 장치를 붙였으면, 바뀐 기억의 옛 값을 다른 기억에서 찾았을 때 그 아래에 `옛 값을 품은 다른 기억 1개를 모델에게 알렸다: local-stack.md (6380).` 같은 줄이 더 뜬다. 넷째 장치의 글은 [넷째 장치가 푸는 것](#넷째-장치가-푸는-것)에 있다.

화면은 알리기만 한다. 기록이나 hook이 실패하면 `기억 기록이 실패했다. 일은 그대로 이어진다. (<오류>)` 한 줄을 내고 exit 0으로 끝나서 사람의 일을 막지 않는다. 넷째 장치만 실패하면 둘째 장치의 줄 아래에 `옛 값 찾기가 실패했다. 기억 기록은 남았고 일은 그대로 이어진다. (<오류>)`를 낸다.

## 기억 폴더와 기록 폴더의 자리

| 폴더 | 자리 |
|---|---|
| 기억 폴더 | user settings에 `autoMemoryDirectory`가 있으면 그 폴더(`~/`는 환경의 `HOME`으로 푼다). 없으면 `$HOME/.claude/projects/<저장소 경로의 영문과 숫자가 아닌 글자를 -로 바꾼 이름>/memory`. 저장소 경로는 git 저장소 뿌리이고, worktree에서는 본 저장소의 뿌리, git 밖에서는 hook 입력의 `cwd`다 |
| 기록 폴더 | 환경 변수 `AML_OVERLAY_JOURNAL_DIR`이 있으면 그 폴더. 없으면 기억 폴더 곁의 `<기억 폴더 이름>-journal`. 예를 들어 `~/agent-memory`의 기록 폴더는 `~/agent-memory-journal`이다 |

기록을 기억 폴더 밖에 두는 까닭은 아래 [판단](#판단)에 있다.

## 기록 폴더의 모양

```text
<기록 폴더>/
├── events.jsonl                 덧붙이기만 하는 원본. 한 줄에 일 하나
├── versions/
│   └── commit-unit.md/
│       ├── 1.md                 판 1의 파일 전체, 글자 그대로
```

### events.jsonl

```json
{"event": "changed", "file": "commit-unit.md", "at": "2026-11-25T09:30:00Z", "session": "s1", "version": 2, "cause": "prompt", "prompt": "커밋은 이제 기능 하나에 하나다, 고쳐"}
```

| 칸 | 뜻 |
|---|---|
| `event` | 일의 종류. `created`(처음 봄), `changed`(바뀜), `deleted`(지워짐), `loaded`(실림), `restored`(되돌림) 가운데 하나 |
| `file` | 기억 파일 이름 |
| `at` | 그 일이 일어난 시각(UTC). 처음 봄과 바뀜은 기억 파일의 mtime이고, 색인 줄만 바뀌었으면 색인의 mtime이다. 지워짐, 실림, 되돌림은 그 일을 잡은 때다 |
| `session` | 그 일이 일어난 세션 id. 모르면 `null` |
| `version` | 판의 번호. 기억 파일마다 1부터 센다. 지워짐은 지워진 판, 실림은 실린 판이다 |
| `cause` | 계기의 종류. 아래 표 |
| `prompt` | 그 답을 시킨 사람의 말 원문. 없으면 `null` |
| `restored_from` | 되돌림에만 있다. 어느 판의 내용으로 되돌렸는지 |

| `cause` | 언제 |
|---|---|
| `prompt` | 답이 끝날 때 잡았고, 그 답을 시킨 사람의 말을 transcript에서 읽었다 |
| `prompt_not_found` | 답이 끝날 때 잡았지만 사람의 말을 읽지 못했다 |
| `outside_session` | 세션이 시작할 때 잡았다. 이 장치를 붙이기 전에 있었거나, 세션 밖에서 바뀌었거나, 끊긴 답에서 바뀐 것이다. 처음 봄이면 파일의 `metadata.originSessionId`를 `session`에 적는다 |
| `session_start` | 실림 |
| `restore_command` | 사람이 부른 되돌리는 명령 |

## 되돌리기

```sh
python3 /path/to/agent-memory-layer/products/overlay/restore.py commit-unit.md 1
```

판 1의 파일 전체를 기억 폴더에 쓰고, 그 판의 색인 줄을 `MEMORY.md`의 같은 파일 줄 자리에 넣는다(줄이 없으면 끝에 더한다). 되돌린 결과는 새 판으로 남으므로 되돌리기도 되돌릴 수 있다. 지워진 기억도 같은 명령으로 되살린다. 기억 폴더는 지금 폴더에서 정하므로, 기본 기억 폴더를 쓸 때는 그 저장소 안에서 부르거나 `--memory-dir`을 준다.

## 판단

| 판단 | 근거 | 다시 열 조건 |
|---|---|---|
| 기록은 기억 폴더 밖에 둔다 | 기준선의 모델은 기억 폴더를 `grep`해서 읽는다. 옛 판을 그 안에 두면 지금 값으로 읽힌다 | 기준선이 기억 폴더 밖까지 뒤지는 것이 시험에서 보일 때 |
| 바뀐 것을 도구 호출마다 잡지 않고, 답이 끝날 때와 세션이 시작할 때 기억 폴더를 기록의 마지막 판과 견준다 | 모델은 `Write`·`Edit`뿐 아니라 shell의 `rm`·`sed -i`로도 기억을 바꾼다(2.1.332의 대화형 세션). 견주는 쪽은 바꾼 길을 가리지 않는다 | 한 답 안에서 같은 기억이 두 번 바뀌어 가운데 판이 빠진 것이 문제가 될 때 |
| 견주는 일은 몇 번 불러도 같은 결과가 되게 한다. 판을 먼저 쓰고 일을 나중에 덧붙이며, 판의 번호는 `events.jsonl`에서 센다 | 같은 기억 폴더를 여러 세션이 함께 쓰고, hook은 중간에 죽을 수 있다. 일 없이 남은 판은 다음 견줌이 덮어쓴다 | — |
| 기록 폴더를 쓰는 동안 파일 잠금을 건다 | 첫째 장치를 붙이면 모든 저장소의 세션이 기록 하나를 함께 쓴다. 판의 번호가 겹치지 않아야 한다 | 잠금이 hook을 눈에 띄게 늦출 때 |
| 판단은 harness를 모르는 함수 넷(`sync`, `record_load`, `restore`, `find_old_value_mentions`)이 하고, hook 스크립트는 입력을 읽어 부르기만 한다 | 같은 핵심을 다른 harness의 hook이나 시험에서 그대로 부른다 | — |
| 세션 밖에서 바뀐 기억에는 세션을 적지 않고, 처음 봄에만 `originSessionId`를 적는다 | 기준선은 기억을 고쳐도 `originSessionId`를 처음 쓴 세션에 둔다. 바뀜에 그 값을 적으면 고친 세션이 틀리게 적힌다 | — |
| 같은 세션 id의 실림은 한 번만 적고, 화면 글은 세션이 시작할 때마다 낸다 | resume과 compact도 같은 id로 시작한다. 같은 기억을 두 번 실렸다고 세면 실린 횟수가 부푼다 | 기준선이 resume이나 compact 때 색인을 다시 싣는지가 실제 세션으로 밝혀질 때 |
| 색인의 글자 상한에 걸친 줄은 실리지 않은 것으로 센다 | 기준선이 상한에서 줄 가운데를 자르는지는 보지 않았다. 걸친 줄의 기억은 링크가 잘렸을 수 있다 | 실제 세션에서 상한에 걸친 줄이 어떻게 실리는지 볼 때 |
| 기억 파일은 기억 폴더 바로 아래의 `MEMORY.md`가 아닌 `*.md`만 센다 | 기준선이 하위 폴더에 기억을 둔 것을 보지 못했다 | 기준선이 하위 폴더에 기억을 쓰는 것을 볼 때 |
| 넷째 장치는 따로 hook을 걸지 않고 둘째 장치의 `Stop` hook 안에서 `sync` 바로 뒤에 돈다 | 모델은 shell의 `rm`·`sed -i`로도 기억을 바꾸므로, 바꾼 길을 가리지 않는 `sync`의 결과에서 출발한다. 답이 끝날 때는 그 답에서 바뀐 기억이 한 묶음으로 보여서 함께 고친 기억을 뺄 수 있다. `Stop` hook을 둘로 나누면 둘이 나란히 돌아 한쪽만 바뀐 것을 본다 | 도구 호출마다 그 결과 곁에 알려야 고치는 비율이 오르는 것이 시험에서 보일 때 |
| 모델에게는 `additionalContext`에 사실로 적어 알리고 `decision: "block"`은 쓰지 않는다 | `Stop`의 `additionalContext`는 hook 오류가 아닌 feedback으로 들어가고 대화가 이어진다. 명령조의 글은 prompt injection 방어에 걸려 사람에게 되묻게 될 수 있다(공식 문서 `hooks.md`, 2026-11-26에 읽음) | 실제 세션에서 모델이 이 글을 사람에게 되묻는 것으로 다룰 때 |
| `stop_hook_active`가 참인 답에서는 기록만 하고 알리지 않는다 | 알림 때문에 이어진 답에서 다시 알리면 한 답이 되풀이된다 | 이어진 답에서 새로 바꾼 값의 옛 값이 다른 기억에 남는 것이 시험에서 보일 때 |
| 값은 backtick 안의 글과, 숫자나 이음 글자를 품은 ASCII 덩어리로 본다. 풀어 쓴 낱말은 값이 아니다 | 영문 낱말까지 값으로 보면 영어로 쓴 기억의 말을 다듬기만 해도 새 값이 생겨 알림이 뜬다. 기준선은 기억을 영어로 쓰기도 한다(2.1.332) | backtick 밖의 이름이 바뀌어 놓친 기억이 시험에서 보일 때 |
| 바뀐 덩어리에 새 값이 생길 때만 옛 값을 찾는다 | 알림은 답 하나를 더 돌게 하므로, 값이 바뀌지 않은 고침에서 말하지 않는 것을 놓치지 않는 것보다 앞에 둔다 | 값을 지우기만 한 고침 뒤에 다른 기억의 옛 값이 실리는 것이 시험에서 보일 때 |
| 사라진 값이 없으면 앞쪽 줄의 값을 모두 옛 값으로 본다 | 기준선은 고치며 옛 값을 본문에 내력으로 남긴다(2.1.332). 글자만으로는 내력과 덧붙인 값을 가르지 못해서, 놓치지 않는 쪽을 고르고 모델이 가리게 한다 | 값을 덧붙이기만 한 고침에 알림이 뜨는 것이 시험에서 보일 때 |
| 옛 값을 뽑을 때와 찾을 때 모두 사실 글만 본다. 구조가 싣는 글자(frontmatter의 `description` 밖의 칸, 색인 줄의 제목·링크 대상·`[scope]`, 기억 사이의 링크)는 값이 아니다 | 구조의 글자는 기억마다 되풀이된다. 셋째 장치를 붙이면 한 저장소의 기억이 모두 같은 `repo` 칸과 `[scope]`를 품고, 같은 세션에 쓴 기억은 같은 세션 id를 품는다. 이 글자가 옛 값으로 뽑히거나 찾는 곳에 들면 한 번의 고침이 모든 기억을 알린다. 2.1.332의 `claude -p` 세션에서 색인 줄을 고친 답이 scope 이름과 자기 파일 이름을 옛 값으로 뽑아 알림이 기억 다섯과 넘친 줄 34개로 찼다 | 제목이나 `name`에만 적힌 값이 바뀌어 놓친 기억이 시험에서 보일 때 |
| `description`, 본문, 색인 줄의 설명을 따로 견준다 | 한 글로 이어 견주면 본문 끝 줄과 색인 줄이 한 덩어리로 묶인다. 본문에서 옛 값을 내력으로 남기면 그 덩어리에서 사라진 값이 없어서, 색인 줄에서 값은 그대로 두고 말만 다듬은 줄의 값까지 옛 값이 된다 | — |
| 지우고 새 이름으로 다시 쓴 기억은, 지운 기억마다 그 답에서 새로 생긴 기억 전부와 견준다 | 기준선은 고칠 때 옛 파일을 지우고 새 이름으로 쓰기도 한다(2.1.332). 새 파일과 옛 파일을 짝짓는 길은 따로 두지 않았다 | 관계없는 지우기와 새로 쓰기가 한 답에 겹쳐 잘못 알린 것이 시험에서 보일 때 |
| 알림 하나에 찾은 줄을 10개까지 담고, 줄에 차례를 매기지 않는다 | `additionalContext`가 10,000자를 넘으면 파일로 빠진다(문서). 상한을 넘던 줄은 구조의 글자에서 나왔고, 사실 글만 찾으면 남는 줄은 모두 옛 값을 글자 그대로 품은 줄이어서 코드가 그 가운데 어느 것이 맞는지 가릴 근거가 없다. 넘친 줄은 개수를 적고, 모델은 알림에 적힌 값으로 기억 폴더를 찾을 수 있다 | 사실 글만 찾아도 줄이 넘쳐 맞는 줄이 밀린 것이 시험에서 보일 때 |
| 알린 일은 기록(`events.jsonl`, `history/`)에 남기지 않는다 | 기록은 기억이 실리고 바뀐 일만 담는다. 알린 글은 transcript에 hook feedback으로 남고, 알림 뒤에 고친 기억은 둘째 장치가 바뀜으로 남긴다 | 알림이 고침으로 이어졌는지를 transcript 없이 세야 할 때 |
| 넷째 장치는 hook 명령의 인자로 켜고 끈다 | 시험 설정의 줄 하나로 장치를 더하고 뺀다. 인자가 없으면 출력과 기록이 둘째 장치만 있을 때와 글자까지 같다 | — |
| 넷째 장치가 실패해도 둘째 장치의 줄은 그대로 낸다 | 바뀜은 이미 기록에 남았고, 되돌리는 명령은 사람이 화면에서 읽어야 한다 | — |

## 확인한 것과 하지 못한 것

| 무엇 | 상태 |
|---|---|
| 핵심 함수와 hook 스크립트 | `python3 -m unittest discover -s tests -t .`(이 폴더에서)로 54개가 통과한다. 임시 HOME과 임시 기억 폴더에서 hook 둘을 손으로 만든 입력으로 불렀다 |
| 넷째 장치의 옛 값 | 위 시험의 `tests/test_old_values.py`가 [옛 값](#옛-값)의 장면마다 찾은 줄을 글자로 댄다. `tests/test_hooks.py`가 `Stop` hook을 process로 띄워 켠 출력, 끈 출력, `stop_hook_active`가 참인 출력을 글자로 댄다. 끈 출력은 둘째 장치만 있을 때의 시험과 같은 글자다 |
| 넷째 장치의 실제 세션 | 2026-11-26에 Claude Code 2.1.332의 `claude -p`(Sonnet 5.5)에서 돌렸다. 사실 글만 보는 지금의 장치로는, 기억 스물넷 가운데 둘이 같은 옛 값을 품고 사람이 그 값을 기억과 다른 이름으로 부르며 고치게 한 세션을 아홉 번 돌렸다. 모델이 한 기억만 고치고 답을 끝낸 세 번 모두 `Stop`의 `additionalContext`가 대화를 이어 가게 했고, 모델이 알림에 적힌 다른 기억을 같은 답에서 고쳤다. 모델이 두 기억을 함께 고친 세 번과, 아무 기억도 고치지 않고 사람에게 되물은 세 번에는 알리지 않았다. 답 안에서 기억이 바뀌거나 지워지는 다른 세션 열두 번(값이 다른 기억에 없는 고침, 새로 쓴 기억을 지우기)에서도 알리지 않았다. 화면 줄은 stream에 `Stop says:` 아래 두 줄로 남았다. 사실 글을 가리기 전의 장치는 같은 폴더에서 색인 줄을 고친 답 하나가 scope 이름과 자기 파일 이름을 옛 값으로 뽑아 알림이 기억 다섯과 넘친 줄 34개로 찼고, 사실 글의 판단이 그것을 근거로 한다. 대화형 세션에서는 같은 폴더로 한 번 봤다. 기억 하나만 고친 답 아래에 `Stop says:` 두 줄이 떴고, 그 아래에 모델에게 간 글이 `Stop hook says:`로 사람 화면에도 그대로 보였다. 모델이 이어서 다른 기억을 고쳤고, 그 답 아래에는 둘째 장치의 줄만 떴다 |
| 실제 세션 | 2026-11-26에 Claude Code 2.1.332(Sonnet 5.5)의 격리된 HOME에서 `claude -p` 세션과 대화형 세션으로 돌렸다. "기억해 둬"로 기억을 남긴 세션과 다음 세션에서 고친 세션의 처음 봄, 실림, 바뀜이 그 답을 시킨 사람의 말과 함께 적혔고, 시각이 세션 기록의 쓴 때와 분까지 같았다. 대화형 세션에서 고친 기억을 되돌리는 명령으로 판 1로 되돌렸다 |
| `Stop` hook 입력에 `session_id`와 `transcript_path`가 온다 | 공식 문서 `hooks.md`(2026-11-25에 읽음)가 모든 hook의 공통 입력으로 적는다. 위 실제 세션에서 바뀜의 줄에 세션 id와 사람의 말이 적힌 것으로 확인했다 |
| `Stop` hook의 `systemMessage`가 사람 화면에 뜬다 | 대화형 세션에서 답 아래에 `Stop says: <글>`로 떴다. `async: true`로 걸면 뜨지 않는다고 문서가 적으므로 그렇게 걸지 않는다 |
| 여러 줄의 `systemMessage`가 줄을 바꿔 뜬다 | 대화형 세션의 첫 화면에 `SessionStart:startup says:` 아래로 기억 열 줄이 줄을 바꿔 떴다 |
| transcript에서 사람의 말을 읽는 법 | transcript의 모양은 공식 문서에 없다. `type`이 `user`이고 `isMeta`가 아니며 `message.content`에 글 조각이 있는 마지막 줄을 그 답을 시킨 말로 읽는다. 위 실제 세션의 세 번(처음 봄 하나, 바뀜 둘)에서 사람의 말이 그대로 읽혔다. 답 하나에 사람의 말이 여럿 끼어든 경우와 요약 뒤는 보지 않았다 |
| 끊긴 답에서 바뀐 기억 | 사람이 끊은 답에는 `Stop`이 돌지 않는다(문서). 그 바뀜은 같은 세션의 다음 답이 끝날 때 다음 말을 계기로 적히거나, 다음 세션이 시작할 때 세션 밖으로 적힌다. 앞의 경우 계기가 틀린다 |
| auto memory를 끈 세션 | settings나 환경 변수로 auto memory를 꺼도 이 장치는 색인을 실린 것으로 센다. 끈 것을 읽지 않는다 |
| 저장소의 settings에 둔 `autoMemoryDirectory` | user settings만 읽는다 |
| 같은 기억 폴더를 함께 쓰는 다른 세션의 바뀜 | 다른 세션이 바꾼 기억을 이 세션의 답이 먼저 끝나며 잡으면, 이 세션과 이 세션의 말을 계기로 적는다. 첫째 장치를 붙이면 일어날 수 있다 |

## 파일

| 파일 | 하는 일 |
|---|---|
| `memory_journal.py` | 핵심. harness를 모른다. `sync`, `record_load`, `restore`, `rebuild_history`와 화면 글 |
| `claude_code.py` | Claude Code adapter. 기억 폴더와 기록 폴더의 자리, transcript에서 사람의 말 읽기, hook 출력(`systemMessage`와 `Stop`의 `additionalContext`) |
| `session_start_hook.py` | `SessionStart` hook. 세션 밖의 바뀜을 견주고, 실린 것을 적고, 화면 글을 낸다 |
| `stop_hook.py` | `Stop` hook. 그 답의 바뀜을 견주어 사람의 말과 함께 적고, 바뀐 것이 있으면 화면 한 줄을 낸다. `--find-old-values`를 받으면 넷째 장치를 돌린다 |
| `old_values.py` | 넷째 장치의 핵심. harness를 모른다. 바뀐 기억의 옛 값을 뽑고, 바뀌지 않은 기억에서 그 값을 품은 줄을 찾아, 모델에게 가는 글과 화면 줄을 짓는다 |
| `restore.py` | 사람이 부르는 되돌리는 명령 |
| `rebuild_history.py` | `history/`를 다시 짓는 명령 |
| `settings.example.json` | user settings에 더할 줄의 예 |
| `tests/` | `unittest`. 핵심 함수를 임시 폴더에서 부르는 시험(`test_memory_journal.py`, `test_old_values.py`)과, hook 스크립트와 명령을 process로 띄우는 시험(`test_hooks.py`) |
| `memory-rules.md` | 셋째 장치의 지시 글. 사람의 지시 파일(`~/.claude/CLAUDE.md`)에 옮겨 넣는다 |
