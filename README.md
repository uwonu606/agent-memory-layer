# agent-memory-layer

코딩 에이전트가 쓰는 기억을 harness 밖의 markdown 파일에 두고, 세션을 연 폴더에 맞는 layer와 그것을 품는 layer의 기억을 load하는 도구다. harness는 모델을 감싸 도구·hook·context를 붙여 주는 프로그램이다. hook은 harness가 정해진 시점에 부르는 스크립트다. layer는 분류된 기억 안에서 기억 파일이 놓이는 폴더 하나다.

기억은 분류된 기억, 미분류, 보류 세 곳 가운데 한 곳에 놓이고, load하는 것은 분류된 기억뿐이다. 기억이 만들어져 분류되기까지 거친 모든 단계는 로그에 한 줄씩 남는다. 이 도구는 아직 만들지 않았다.

## 문제

에이전트가 쓰는 기억이 **관리가 되지 않는다.** 만든 사람이 써 보니 Claude Code의 auto memory는 기억을 쓰고 읽는 일이 모두 자동으로 돌고 사람이 읽기 어려워서, 기억을 관리할 수 없었다. 걸린 곳은 아래 넷이다. 항목마다 만든 사람이 겪은 것 뒤에 Claude Code 문서가 적은 auto memory의 동작을 붙인다.

- 무엇이 언제 쓰였는지 모른다. 문서는 Claude가 세션 도중에 무엇을 남길지 스스로 고르고, 쓴 시각은 그 파일 frontmatter의 `modified`에 남는다고 적는다.
- 기억 파일이 저장소마다 흩어져 있고 폴더 이름을 읽기 어렵다. 문서는 기억 폴더가 git 저장소마다 `~/.claude/projects/<project>/memory/`에 따로 있고, `<project>`는 저장소가 놓인 경로에서 딴 이름이라고 적는다.
- 틀리거나 낡은 기억을 찾아 고치기 어렵다. 문서는 기억이 사람이나 Claude가 고치거나 지울 때까지 남는다고 적는다.
- 사람이 묻지 않으면 이번 세션에서 무엇이 load되고 recall됐는지 알 수 없다. recall은 세션 도중에 기억을 더 꺼내 오는 일이다. 문서는 세션 시작에 index인 `MEMORY.md`의 앞부분만 load되고 기억 하나하나가 든 파일은 Claude가 필요할 때 읽는다고 적고, load된 파일은 사람이 `/context`를 실행하면 보인다고 적는다. 문서에서 recall은 changelog에 이름만 나오고, 무엇을 언제 하는지는 적혀 있지 않다.

## 만들 것

load하는 hook 스크립트(`mem-hook`)와, 쓰기 호출을 로그에 적는 hook과, 에이전트가 기억을 만들어 분류하는 길을 만든다. hook은 상주 프로세스 없이 파일만 읽고 쓴다. `mem-hook`은 작업 위치로 받는 layer를 찾아 그 기억을 load한다. 작업 위치는 세션을 연 폴더이고, 세션 도중 에이전트가 다른 폴더로 옮겨도 바뀌지 않는다. hook 스크립트는 Python 3으로 쓰고, 기대는 것은 `python3`와 standard library뿐이어서 설치할 패키지가 없다. 버전 하한은 적지 않고 돌려서 확인한 버전만 적는다. 이 기기에 깔린 것은 Python 3.14.4다. 다른 기기로 옮길 때는 그 기기에서 돌려 보고 하한을 적는다. `mem-hook`과 쓰기 호출을 로그에 적는 hook은 한쪽이 깨져도 다른 쪽이 돌아야 해서 파일 둘로 따로 둔다. `python3`가 PATH에 없어 스크립트가 돌지 못하면 세션 시작 줄이 뜨지 않는다. 이 경우는 따로 다루지 않고, 줄이 뜨지 않을 때의 알림 모양은 아직 정하지 않았다.

Claude Code의 auto memory는 끈다. 켜 두면 같은 것이 두 곳에 쌓여서, 답에 쓰인 것이 어느 쪽에서 왔는지 가를 수 없기 때문이다.

Claude Code 밖에서도 쓴다는 요구를 둔다. Claude Code부터 만들고 Codex는 만들지 않는다. 겨누는 크기는 만든 사람 자신이 auto memory를 끄고 이 도구로 일하는 것이다.

도구가 이 구조여야 하는 까닭을 만든 사람이 직접 세워 보며 이해하는 것이 이 프로젝트의 목적이어서, 기억을 markdown으로 두는 기존 오픈소스를 쓰지 않고 직접 만든다.

문제는 "관리가 되지 않는다" 하나이고 걸린 곳은 #문제의 넷이다. 이 도구는 다른 일의 기억이 섞여 나오는 것을 막겠다고 약속하지 않는다. 섞이는 일이 다시 생기고 기억 탓으로 확인되면 #문제에 넣는다.

## 기능

가장 작은 것부터 만들고 한 단계씩 얹는다. 단계마다 그 단계에서 조용히 일어날 실패를 보이는 줄을 같이 얹는다. 먼저 만드는 것은 1단계뿐이다. 아래 표는 단계마다 하는 일과 같이 보이는 줄을 보인다.

| 단계 | 하는 일 | 같이 보이는 줄 |
|---|---|---|
| 1 | 작업 위치로 받는 layer를 찾아 세션 시작과 compaction(대화가 길어져 harness가 앞 내용을 줄이는 일) 뒤에 load한다. 에이전트가 요청과 판단으로 원문을 쓰고, 넘김 기준을 거쳐 변환과 분류를 하고, 모든 단계를 로그에 남긴다 | 세션 시작 줄(load한 목록, 보류·미분류 건수, 넘음 표시) |
| 이후 | decision은 고치지 않고 새 파일로 쌓고, 옛 decision은 load하지 않는 자리로 옮긴다 | 얹을 때 정한다 |

이후 단계를 얹는 때와 세부는 아직 정하지 않았다.

1단계는 걸린 곳 넷을 줄이는지로 판정한다. 사람이 묻지 않고 알 수 있는지로 가른다. 예를 들어 이번 세션에서 load된 것을 세션 시작 줄만 보고 답할 수 있는지, 이 기억이 언제 왜 쓰였는지를 로그만 보고 답할 수 있는지, 낡은 기억을 찾아 고치게 시켜 끝까지 되는지를 본다. 같은 일을 auto memory에 시켜 견준다.

판단이 알맞은지는 판정에 넣지 않고 로그를 사람이 훑어 본다. 판정의 칸과 테스트는 아직 정하지 않았다.

## 설계와 까닭

### `~/.mem`의 모양

`~/.mem` 아래에 곳 셋과 파일 둘이 나란히 있다. 규칙 파일만 `~/.mem-hook`에 있다. 아래 그림은 이 자리를 보인다.

```
~/.mem/
  sorted/       분류된 기억. hook이 load한다
  unsorted/     미분류
  hold/         보류
  glossary.md   기억 용어집. 변환하는 에이전트가 읽는다. 세션 시작에 load하지 않는다
  criteria.md   기억 기준. hook이 읽어 preamble과 함께 실어 준다
~/.mem-hook/layer-rules
```

`sorted/` 안은 layer tree다. 폴더가 폴더를 품고, `sorted/` 뿌리에 놓인 md가 전역 항목이어서 모든 세션이 받는다. layer 이름은 사람이 붙이고 기억 용어집이 지킨다. 아래 그림에서 `work`·`api`·`web`과 파일 이름은 예시다.

```
~/.mem/sorted/
  a.md              전역
  work/b.md         전역 안에 놓인 layer
  work/api/c.md     work 안에 놓인 layer
  work/web/d.md     work 안에 놓인 layer
```

작업 위치에 맞는 layer가 `work/api`뿐인 세션은 `a.md`·`b.md`·`c.md`를 받는다. 맞는 layer가 `work`뿐인 세션은 `a.md`·`b.md`만 받는다. 받는 layer 안에 놓인 layer는 받지 않기 때문이다.

- 항목 하나는 md 파일 하나이고 제목은 파일 이름이다.
- 도구가 정한 이름(`unsorted/`, `hold/`, `glossary.md`, `criteria.md`)은 layer가 놓이는 `sorted/` 안에 없다. 그래서 사람이 붙인 layer 이름과 부딪힐 자리가 없다.
- 로그와 원문 보관의 자리는 아직 정하지 않았다.

### 기억이 만들어져 분류되기까지

기억이 만들어지는 길은 둘이고, 둘 다 1단계에 든다.

- **요청**: 사용자가 "기억해 둬"라고 시킨 것. 사람의 필요를 반영해 쓴다.
- **판단**: 에이전트가 기억 기준에 따라 알아서 고른 것.

둘은 출처가 달라서 기억 파일의 `출처` 필드(요청 또는 판단)로 구분한다. 요청에서 나온 원문은 넘김 기준을 거치지 않는다. 사람이 이미 고른 것을 에이전트가 다시 걸러 내면 말한 것이 실리지 않는 조용한 실패가 생기기 때문이다.

한 기억이 거치는 단계는 아래 흐름이다. 단계는 폴더가 아니라 과정이다. 지점마다 저장하지 않고, 남길 이유가 있는 것만 남긴다.

```
판단 ─▶ 넘김 기준 ─▶ 변환(기억 용어집) ─▶ 분류 ─▶ 분류된 기억 (hook이 load)
         │ 미달         │ 못 맞춤            │ 못 정함
         └──▶ 보류      └────────────────────┴──▶ 미분류
```

| 단계 | 하는 일 |
|---|---|
| 판단 | 에이전트가 기억할 만한지 본다 |
| 넘김 기준 | 쓴 글을 변환하고 분류해도 되는지 가른다. 맥락(세션을 모르는 사람이 읽어도 뜻이 서는가)과 형태(기억 용어집의 낱말로 맞춰 layer 하나에 항목 하나 크기로 놓이는가)를 본다 |
| 변환 | 원문을 기억 용어집의 낱말로 맞춰 기억 항목으로 고쳐 쓴다 |
| 분류 | 변환한 항목을 놓을 layer를 정해 옮긴다 |
| 보류 | 넘김 기준에 미달해 사람이 내용을 채워야 하는 원문이다 |
| 미분류 | 넘김 기준은 통과했지만 변환이나 분류를 끝내지 못해, 분류만 정하면 되는 것이다 |

넘김 기준은 에이전트가 원문을 쓴 직후 그 원문과 보류에 남은 원문을 함께 비춰 본다. 새 원문이 생길 때마다 다시 보고, 사람이 말하면 언제든 정리한다. 보류는 새 원문이 내용을 채워 주기도 하고, 사람이 말로 시켜 에이전트가 채우기도 한다.

변환에서 맞는 낱말이나 layer 이름이 없으면, 에이전트가 사람에게 묻지 않고 새 이름을 더하고 변환 결과에 새 이름을 한 줄로 알린다.

분류된 글이 10,000자를 넘으면 분류가 그 layer 안에 더 좁은 layer를 만들어 항목을 옮긴다. 넓은 layer에는 그 아래 전부에 맞는 항목만 남긴다.

변환 전 원문은 읽기 전용 파일로 로그 옆에 보관하고, 변환 뒤에도 원문과 변환본을 견주어 본다. 보관 자리는 아직 정하지 않았다.

### layer 규칙

layer 규칙은 작업 위치를 layer에 잇는 규칙이다. 열쇠는 작업 위치다. 의미로 나누는 일은 layer 이름이 맡고, 고르는 일은 작업 위치가 맡는다.

규칙은 `~/.mem-hook/layer-rules` 파일 하나에 `<layer>: <경로>` 줄로 적는다. layer는 `~/.mem/sorted` 안의 폴더 경로여서, `work/api`는 `~/.mem/sorted/work/api/`다. 파일이 `~/.mem` 옆에 놓여서 `ls -a ~`에서 함께 보인다. `~/.config` 아래에 두면 `XDG_CONFIG_HOME`을 따를지를 더 정해야 하고, 따르면 환경에 따라 자리가 달라진다.

한 작업 위치에 줄이 여럿 맞을 수 있다. 맞는 layer가 서로 품지 않아도 실패가 아니다. 세션이 받는 layer는 작업 위치에 맞는 layer 전부와 그 layer를 품는 layer 전부를 합친 것이고, 순서와 우선순위가 없다. 전역은 줄에 적지 않고 모든 세션이 받는다.

아래 줄은 예시다. 한 layer에 경로가 여럿이면 같은 layer로 줄을 여럿 쓴다.

```
work: ~/workspace/work
work: /mnt/c/workspace/work
work/api: ~/workspace/work/api-server
oss/lib: ~/workspace/work/shared-lib
```

위 줄로 세션을 열었을 때 받는 layer를 아래 표가 보인다.

| 세션을 연 폴더 | 맞는 layer | 세션이 받는 layer |
|---|---|---|
| `~/workspace/work/api-server/src` | `work`, `work/api` | 전역, `work`, `work/api` |
| `~/workspace/work/shared-lib` | `work`, `oss/lib` | 전역, `work`, `oss`, `oss/lib` |
| `/mnt/c/workspace/work/web` | `work` | 전역, `work` |
| `~/workspace/work-old` | 없다 | 전역 |
| `~/notes` | 없다 | 전역 |

줄 형식과 경로 규칙은 아래와 같다.

- 줄에서 처음 나오는 `: `(colon과 빈칸)에서 가르고 그 뒤는 전부 경로로 읽는다. 경로를 뒤에 두면 경로에 빈칸이나 colon이 있어도 따옴표 없이 적는다.
- 경로는 `/`나 `~`로 시작하고, 줄에는 symlink를 지나지 않는 실제 경로만 적는다. hook은 줄 머리의 `~`를 home의 실제 경로로 풀고 끝의 `/`를 뗀다. 대소문자를 가른다. Claude Code가 hook에 주는 작업 위치는 symlink를 푼 실제 경로여서, 줄에도 실제 경로만 있으면 사람이 줄과 작업 위치를 글자로만 견주어 맞힌다.
- 작업 위치가 줄의 경로와 같거나 그 아래에 있으면 그 줄의 layer가 맞는다. 폴더 이름 단위로 맞춘다(`~/workspace/work`는 `~/workspace/work-old`에 맞지 않는다).
- 이 기기에 없는 경로는 풀어 보지 않는다. 없는 경로를 적은 줄은 어떤 세션에도 맞지 않는다. 작업 위치는 이 기기에 있는 폴더여서, 없는 경로를 적은 줄은 맞을 세션이 없기 때문이다.
- 줄의 순서에는 뜻이 없고 빈 줄은 건너뛴다. `#`로 시작하는 줄은 건너뛴다.
- `layer-rules`가 없는 것은 실패가 아니고 전역만 load한다. 처음 설치한 기기의 상태이기 때문이다.
- 줄이 가리키는 layer 폴더가 `sorted/`에 없는 것도 실패가 아니고 빈 layer로 본다. 첫 기억을 쓰기 전인 layer의 상태이기 때문이다. hook은 폴더를 만들지 않는다.

읽지 못하는 줄이 있으면 hook은 그 줄만 건너뛰고 나머지 줄은 적용하며, 세션 시작 줄에 읽지 못한 줄을 알린다. 읽지 못하는 줄은 아래 넷이다.

- `: `가 없는 줄.
- layer가 비었거나 `sorted/` 밖을 가리키는 줄(`/`로 시작하거나 `..`가 든 것).
- 경로가 `/`나 `~`로 시작하지 않는 줄.
- 경로가 symlink를 지나는 줄. hook은 `~`를 풀고 끝의 `/`를 뗀 경로를 symlink까지 풀어 보고, 풀어 본 경로가 풀어 보기 전과 다르면 symlink를 지난다고 본다.

Claude Code에서 hook은 작업 위치를 환경 변수 `CLAUDE_PROJECT_DIR`에서 읽고, hook 입력의 `cwd`는 쓰지 않는다. `cwd`는 에이전트가 `cd`하면 옮긴 폴더를 따라가서, `cwd`로 읽으면 compaction 뒤에 받는 layer가 바뀌기 때문이다.

Claude Code의 hooks 문서는 `CLAUDE_PROJECT_DIR`을 "the project root where the session started"라고 적고, `cwd`를 "Current working directory when the hook is invoked"라고 적는다. `SessionStart` hook의 입력 JSON에 세션을 연 폴더를 주는 필드는 그 문서의 필드 목록에 없다.

새 저장소는 규칙에 한 번 적은 경로 아래에 만들기만 하면 규칙을 고치지 않아도 제 layer에 든다.

### 누가 무엇을 하나

아래 표는 사람, 에이전트, hook이 하는 일과 하지 않는 일을 보인다.

| 누가 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 사람 | layer 규칙을 정한다. 기억 기준과 기억 용어집을 고칠 일, 요청할 기억, 보류를 채울 내용, 고치거나 지울 일을 에이전트에게 말로 시킨다. `~/.mem`과 세션 시작 줄을 기존 markdown 뷰어와 터미널로 보고 로그를 훑는다 | 기억 파일을 손으로 쓰거나 옮기지 않는다 |
| 에이전트 | 요청받은 것과 기억 기준으로 고른 것을 원문으로 쓴다. 넘김 기준 검사, 변환, 분류를 하고 새 이름을 기억 용어집에 더한다. 에이전트가 적는 로그 줄을 쓴다 | 지시 파일(CLAUDE.md·AGENTS.md)을 건드리지 않는다. 사람을 부르지 않는다 |
| hook | load하고 세션 시작 줄을 띄운다. 쓰기 호출을 로그에 적는다 | 항목을 바꾸지 않는다. 무엇을 save할지 판단하지 않는다. 사람을 부르지 않는다 |

### 1단계가 load하는 방식

`mem-hook`이 `SessionStart` hook으로 돈다. 작업 위치로 받는 layer를 찾고, preamble, `criteria.md`, 전역부터 받는 layer까지 각 layer의 항목을 그 순서로 이어 `additionalContext`로 넣고, 세션 시작 줄을 `systemMessage`로 띄운다. preamble은 hook이 기억 앞에 붙이는 지시 글이다. `sorted/` 밖(`unsorted/`, `hold/`, `glossary.md`)은 load하지 않는다.

- **preamble**: 첫 문장은 load된 기억이 지시 파일과 사용자가 말하지 않을 때만 따르는 기본값이라고 이른다. 기억이 지시 파일이나 사용자 말과 부딪힐 때의 기준이다. 나머지 글(판단·넘김·변환·분류·로그를 어떻게 하라는 지시)은 아직 정하지 않았다.
- **시점**: startup·clear·compact에서 돈다. resume에서는 돌지 않는다. `fork`로 시작할 때와 resume 때의 시점은 아직 정하지 않았다.
- **10,000자 넘음**: 상한 없이 다 넣고 세션 시작 줄에 `10,000자 넘음`을 붙인다. Claude Code는 넣는 글이 10,000자를 넘으면 그 글을 파일로 돌리고, 모델에게는 그 파일의 경로와 앞 2,000자까지의 미리보기만 준다. Claude Code는 모델에게 그 파일을 읽으라고 시키지 않는다. 그때는 세션 시작 줄이 모델이 받은 것과 다르다. 넘칠 때 색인으로 가는지는 아직 정하지 않았다.
- **md가 아닌 파일**: `sorted/` 안에서 load하지 않고 세션 시작 줄에 이름을 띄운다. 줄의 모양은 아직 정하지 않았다.

세션 시작 줄에는 load한 파일 목록(예: `실림: style.md, work/api-naming.md (1,240자)`), 보류와 미분류 건수, `10,000자 넘음`, 읽지 못한 layer 규칙 줄, md가 아닌 파일의 이름을 띄운다. 줄의 모양은 아직 정하지 않았다.

### 기억 용어집과 기억 기준

기억 용어집은 기억 안에서 쓰는 낱말의 뜻과 layer 이름을 한 곳에 정해 둔 파일이다. 에이전트가 쓰고 사람은 말로 시킨다. 같은 사실에 이름 둘이 생기거나 같은 낱말에 뜻 둘이 생기는 것을 막는다. 변환하는 에이전트가 참조한다.

기억 기준은 무엇이 기억할 만한지와 무엇을 넘길지를 적은 파일이다. 사용자의 말에서 나오고 에이전트가 쓴다. hook이 읽어 세션에 실어 준다.

두 파일의 첫 모양은 아직 정하지 않았다.

### 로그

기억이 만들어져 분류되기까지 거친 모든 단계가 로그에 한 줄씩 남는다. 판단, 원문 씀, 넘김, 보류, 미분류, 새 이름 더함, 분류, 세션 시작 load가 여기에 든다. 시각과 보류 이유는 파일이 아니라 로그에 둔다.

줄을 hook이 적는 것(Claude Code에서 쓰기 호출을 보고 적는다)과 에이전트가 적는 것을 출처로 나눈다. 보장하는 범위는 hook이 본 것까지(쓴 것까지)다. 쓰지 않기로 한 판단은 도구 호출이 없어서 hook이 볼 사건이 없고, 에이전트가 적을 때만 남는다.

로그에는 덧붙이기만 하고 고치거나 지우지 않는다. 로그는 사람이 찾고 정리하는 길이 있다. 로그의 자리와 줄 형식은 아직 정하지 않았다.

### 필드

기억 파일에는 `출처` 하나만 둔다(요청 또는 판단). 이름과 자리는 아직 정하지 않았다.

필드는 이미 정한 규칙 하나가 읽는 것만 둔다. 같은 정보는 한 곳에만 둔다(상태와 소속은 폴더 위치, 시각과 이유는 로그). 에이전트가 쓰는 값은 빠질 수 있어서 파일 필드를 최소로 둔다.

기억 용어집 항목은 낱말, 뜻, 쓰지 않는 이름, layer 이름인지를 담는다. 형식은 아직 정하지 않았다.

## 본질

이 도구의 구조에서 지켜지는 제약 가운데, 빼면 어떤 성질이 사라지는지로 본질을 가른다. 새 요구는 이 제약을 깨서 아래 성질을 잃게 하는지로 거른다.

**정체성을 정하는 제약: 모든 단계가 추적된다.** 기억이 만들어져 분류되기까지 거친 단계가 로그에 한 줄씩 남고, 끝까지 못 간 것은 `hold/`나 `unsorted/`에 남는다. 사람이 이 제약을 보고 만지는 곳은 로그, `hold/`와 `unsorted/`, 세션 시작 줄이다.

아래 표는 이 제약과 함께 지키는 제약과, 그 제약이 낳는 성질을 보인다.

| 제약 | 낳는 성질 | 빼면 사라지는 것 |
|---|---|---|
| 기억의 원본은 `~/.mem/` 아래 사람이 읽는 md 파일이고, 서버나 DB는 두지 않는다 | 사람과 에이전트가 같은 원본을 `ls`·`grep`·에디터로 본다 | 원본을 보는 길이 서버나 DB를 여는 도구로 좁아진다 |
| load는 hook이 세션 시작에 한다. 에이전트의 자발적 호출에 맡기지 않는다 | 무엇이 load되는지가 모델 판단에 달리지 않는다 | load가 매번 일어난다는 보장 |
| 상주 프로세스 없이 파일만 읽고 쓰는 hook 스크립트로 둔다 | 죽을 프로세스가 없고 한 사람이 전체를 읽는다 | 프로세스가 죽으면 load가 빠진다 |
| load된 파일 목록과 보류·미분류 건수를 세션 시작 줄로 터미널에 띄운다 | 사람이 묻지 않아도 이번 세션의 재료를 안다 | 사람이 묻지 않으면 무엇이 load됐는지 알 수 없다 |
| layer 이름과 낱말의 뜻은 기억 용어집 한 곳이 정한다 | 같은 사실에 이름이 둘 생기지 않는다 | 이름이 어긋난 기억을 찾기 어려워진다 |

제약에서 벗어나는 것은 아직 정하지 않았다. 새 요구는 이 본질에 대 본 뒤에 받는다.
