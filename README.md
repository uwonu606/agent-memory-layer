# agent-memory-layer

코딩 에이전트가 쓰는 기억을 harness 밖의 markdown 파일에 두고, 세션을 연 작업 위치에 맞는 폴더의 기억만 load하는 도구다. harness는 모델을 감싸 도구·hook·context를 붙여 주는 프로그램이고, 여기서는 Claude Code와 Codex를 말한다. hook은 harness가 정해진 시점에 부르는 스크립트다. 이 도구는 아직 만들지 않았다.

## 문제

에이전트가 기억을 쓰는 방식에서 두 가지가 걸린다.

- **범위가 맞지 않는다.** 회사 일, 오픈소스 기여처럼 저장소 여럿이 묶이는 일을 이 글에서는 **맥락**이라고 부른다. Claude Code의 auto memory는 저장소마다 기억을 갈라서, 저장소를 넘는 사실이 다른 저장소의 기억에만 있으면 load되지 않는다. 반대로 에이전트가 한 맥락의 세션에서 다른 맥락의 이야기를 꺼내 온 적이 있지만, 그 이야기가 기억에서 왔는지는 확인하지 못했다.
- **세션 시작에 무엇이 load됐는지 보이지 않는다.** 사람이 묻지 않으면 이번 세션에서 에이전트가 어떤 기억을 받았는지 알 수 없다.

## 만들 것

작업 위치로 맥락 폴더를 골라 전역과 그 폴더의 기억만 load하는 hook 스크립트 하나(`mem-hook`)다. 작업 위치는 세션을 연 폴더다. 상주 프로세스 없이 파일만 읽고 쓴다. Claude Code부터 만든다.

도구가 이 구조여야 하는 까닭을 만든 사람이 직접 세워 보며 이해하는 것이 이 프로젝트의 목적이어서, 기억을 markdown으로 두는 기존 오픈소스를 쓰지 않고 직접 만든다.

## 기능

가장 작은 것부터 만들고 한 단계씩 얹는다. 단계마다 그 단계에서 조용히 일어날 실패를 보이는 줄을 같이 얹는다. 먼저 만드는 것은 1단계뿐이다.

| 단계 | 하는 일 | 같이 보이는 줄 |
|---|---|---|
| 1. load | 작업 위치로 맥락 폴더를 골라, 전역과 그 폴더의 기억을 세션 시작과 compaction 뒤에 load한다 | 세션 시작 줄: `실림: style.md, work/api-naming.md (1,240자)` |
| 2. save | 에이전트가 배운 것을 묻지 않고 save한다. 쓰기 전에 맥락 폴더에서 같은 것을 먼저 찾는다 | log: `~/.mem/log.md`에 쓰기마다 한 줄 |
| 3. decision | decision은 고치지 않고 새 파일로 쌓는다. 옛 decision은 load하지 않는 자리로 옮긴다 | log에 남는 옮긴 줄 |
| 4. split | 넘치면 맥락 규칙에 더 좁은 줄을 더해 맥락 폴더를 split한다 | 세션 시작 줄의 넘음 표시 |

겨누는 크기는 만든 사람 자신이 auto memory를 끄고 이 도구로 일하는 것이다. 1단계는 다른 맥락의 기억이 load되지 않는지를 기존 auto memory와 견주어 판정한다. 2단계부터의 판정은 그 단계를 얹을 때 정한다.

## 설계와 까닭

### 저장소 모양

```
~/.mem/
  contexts          맥락 규칙
  *.md              전역. 어디서나 load된다
  work/*.md         맥락. 작업 위치가 work 규칙에 맞을 때 load된다
  oss/*.md
  oss/.history/     load하지 않는 자리. 3단계부터
  log.md            log. 2단계부터
```

항목 하나는 md 파일 하나이고 제목은 파일 이름이다. 범위는 항목이 놓인 폴더가 정한다. hook은 전역과 고른 맥락 폴더 바로 아래의 md만 load하고, 그 아래 폴더는 load하지 않는다.

저장소 하나에서만 load되는 층은 두지 않는다. 맥락을 넘는 사실은 전역에 둔다.

### 맥락 규칙

`~/.mem/contexts`의 한 줄은 맥락 이름과 경로 하나다.

```
work     ~/workspace/work/
oss      ~/workspace/oss/
work     /mnt/c/workspace/work/
```

hook은 작업 위치(hook 입력의 `cwd`)가 위에서부터 처음 맞는 줄의 경로로 시작하면 그 이름의 폴더를 맥락으로 고른다. 맞는 줄이 없으면 전역만 load한다. 한 번 적은 경로 규칙이 그 아래 저장소 전부에 걸리므로, 새 저장소는 규칙의 경로 아래에 만들기만 하면 제 맥락에 든다.

### 누가 무엇을 하나

| 누가 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 사람 | 맥락 규칙을 정한다. `~/.mem`과 세션 시작 줄을 기존 markdown 뷰어와 터미널로 본다. save하거나 고치거나 지울 일을 에이전트에게 말로 시킨다 | 기억 파일을 손으로 쓰거나 옮기지 않는다 |
| 에이전트 | 1단계에서는 사람이 시킬 때 `~/.mem` 아래 md를 쓰고 고치고 지운다. 2단계부터는 배운 것을 묻지 않고 save한다 | 지시 파일(CLAUDE.md·AGENTS.md)을 건드리지 않는다 |
| hook | load하고, 세션 시작 줄을 띄운다. 2단계부터 log에 덧붙인다 | 항목을 바꾸지 않는다. 무엇을 save할지 판단하지 않는다. 사람을 부르지 않는다 |

Claude Code의 auto memory는 끈다. 켜 두면 같은 것이 두 곳에 쌓여서, 답에 쓰인 것이 어느 쪽에서 왔는지 가를 수 없기 때문이다.

### 1단계가 load하는 방식

`mem-hook`이 SessionStart hook으로 돈다. 맥락 규칙으로 맥락을 고르고, preamble·전역 항목·맥락 항목을 이어 `additionalContext`로 넣고, 세션 시작 줄을 `systemMessage`로 띄운다.

| 규칙 | 값 | 까닭 |
|---|---|---|
| preamble | load된 기억은 지시 파일과 사용자가 말하지 않을 때만 따르는 기본값이라고 이르고, 기억을 save하라는 말을 들으면 고른 맥락 폴더(어디서나 필요한 것은 전역)에 md 파일 하나로 쓰라고 이른다 | 첫 문장은 기억이 지시 파일이나 사용자 말과 부딪힐 때의 기준이다. 둘째 문장은 쓸 곳을 이른다. 쓸 곳이 틀리면 범위가 틀린다 |
| 시점 | startup·clear·compact. resume은 넣지 않는다 | compaction 뒤 비는 context window를 다시 채운다. resume은 앞 대화에 `additionalContext`가 이미 있다 |
| 10,000자 넘음 | 상한 없이 다 넣고 세션 시작 줄에 `10,000자 넘음`을 붙인다 | Claude Code는 넣는 글이 10,000자를 넘으면 그 글을 파일로 돌리고, 모델에게는 그 파일의 경로와 앞 2,000자까지의 미리보기만 준다. Claude Code는 모델에게 그 파일을 읽으라고 시키지 않는다. 그때는 세션 시작 줄의 `실림`이 모델이 받은 것과 다르다 |

### 2단계 log

log `~/.mem/log.md`에는 덧붙이기만 하고 고치거나 지우지 않는다. hook은 세션 시작과 compaction 뒤에는 load된 경로를, 에이전트가 `~/.mem`을 쓰거나 고치거나 지울 때마다 시각·맥락·경로(shell 명령이면 명령 원문)와 그 줄을 부른 사람의 말을 transcript에서 찾아갈 `p=`를 적는다. 항목 본문과 바꾼 내용은 담지 않는다. 사람이 뒤에 log를 보고 고치거나 지우라고 시키는 이 방식을 사후 검토라고 부른다.

### 3단계 decision

한번 쓴 decision은 고치지 않고, 바꿀 때 새 decision을 쓴다. 대체된 decision은 맥락의 `.history/`로 옮긴다. hook은 맥락 폴더 바로 아래의 md만 load하기 때문에, 옮긴 decision은 계산 없이 load에서 빠진다.

### 4단계 split

세션 시작 줄에 넘음 표시가 뜨면 `~/.mem/contexts`의 위쪽에 더 좁은 경로의 줄을 더하고 그 이름의 폴더로 항목을 옮긴다. hook이 처음 맞는 줄을 고르기 때문에 더 좁은 줄이 위에 있어야 한다. 모델이 index를 읽고 고르게 하는 것은 그다음이다.

## 본질

이 도구의 구조에서 지켜지는 제약 가운데, 빼면 어떤 성질이 사라지는지로 본질을 가른다. 새 요구는 이 제약을 깨서 아래 성질을 잃게 하는지로 거른다.

### 정체성을 정하는 제약

**범위는 자리다.** 기억은 언제나 놓인 폴더가 정한 곳에서만 load된다.

모델이 범위를 고르면 빠뜨려도 알기 어렵기 때문에, load될 곳을 모델이 고르지 않고 폴더와 맥락 규칙이 정한다. 그래서 다른 일의 기억이 딸려 오지 않고, 무엇이 load되는지가 `ls`로 보인다.

사람이 이 제약을 보고 만지는 곳은 `~/.mem/<맥락>/` 폴더, `~/.mem/contexts`, 세션 시작 줄의 경로다.

### 이 제약과 함께 지키는 것

| 제약 | 낳는 성질 | 빼면 사라지는 것 |
|---|---|---|
| 기억의 원본은 `~/.mem/` 아래 사람이 읽는 md 파일이고, 서버나 DB는 두지 않는다 | 사람과 에이전트가 같은 원본을 `ls`·`grep`·에디터로 본다 | 원본을 보는 길이 서버나 DB를 여는 도구로 좁아진다 |
| load는 hook이 세션 시작에 한다. 에이전트의 자발적 호출에 맡기지 않는다 | 무엇이 load되는지가 모델 판단에 달리지 않는다 | load가 매번 일어난다는 보장 |
| 맥락의 항목은 고르지 않고 전부 load한다. 검색 성능은 기준에 두지 않는다 | load된 것이 폴더의 파일 목록과 같다 | load된 것을 `ls`로 아는 길. 고르는 쪽이 범위를 정하게 된다 |
| 상주 프로세스 없이 파일만 읽고 쓰는 hook 스크립트 하나로 둔다 | 죽을 프로세스가 없고 한 사람이 전체를 읽는다 | 프로세스가 죽으면 load가 빠진다 |
| load된 항목의 경로를 세션 시작 줄로 터미널에 띄운다 | 사람이 묻지 않아도 이번 세션의 재료를 안다 | 사람이 묻지 않으면 무엇이 load됐는지 알 수 없다 |
| `~/.mem`의 변경을 log 한 줄로 남긴다 | 묻지 않고 쓰게 해도 뒤에 따라갈 수 있다 | 묻지 않고 쓴 것을 뒤에 따라갈 길 |

1단계에는 log가 없어서 마지막 행을 지키지 않는다. 2단계에서는 에이전트가 쓸 때마다 한 줄을 남기는 데까지 지킨다. 에디터로 고친 것과 바꾼 내용은 2단계에서도 log에 남지 않는다.

### 제약에서 벗어나는 것

이 제약은 무엇을 만드는지를 분명히 제한하려고 정했다. 아래는 이 제약에서 벗어나서 지금은 만들지 않는 것이다. 기준이 분명해지고 부족한 부분이 생기면 이 본질부터 다시 열어 추가한다.

| 제약에서 벗어나는 것 | 까닭 |
|---|---|
| frontmatter나 metadata로 load될 곳 정하기, 항목에 "이럴 때만 쓴다" 적기 | 자리가 아닌 것이 범위를 정하게 된다 |
| 모델이 index·낱말 trigger·vector 검색으로 골라 load하기 | 모델이 범위를 고르면 빠뜨려도 모른다 |
| hook 말고 기억을 load하는 다른 길(MCP 검색 같은 것) | 범위를 지나지 않는 길이 생긴다 |
| 폴더에 놓인 항목을 계산으로 빼기 | 놓인 곳과 load되는 곳이 달라진다 |

새 요구는 이 본질에 대 본 뒤에 받는다.
