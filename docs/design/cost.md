# 비용

기억 도구가 쓰는 사용량과 시간, 차지하는 context 자리가 왜 불어나고, 얼마나 들고, 어떻게 줄이는지를 적는다. 이 순서로 따지는 까닭은 [판단과 방향](../direction.md)에 있다.

여기 적은 규칙은 모든 제품이 갖춘다. 제품마다 달리 만들어 견주는 자리와 뺀 것은 [설계의 입구](../design.md)의 표에 있고, 낱말의 뜻은 [용어집](../../GLOSSARY.md)에 있다.

## 불어나는 구조

비용은 세 몫으로 불어난다.

| 몫 | 무엇에 곱해지나 | 붙는 자리 |
|---|---|---|
| 일의 길이 | 세션의 모델 요청 수, 사람의 말 수, 도구 호출 수 | 실린 글은 그 뒤의 모든 모델 요청에서 다시 읽힌다. 검사는 도구 호출마다, 싣기는 싣는 자리마다 돈다. 이어 여는 세션마다 한 벌씩 더 싣는 것도 이 몫이다 |
| 쌓인 기억의 수 | 기억의 수 | 기억의 목록 전체가 입력이 되는 자리 넷이다. 상한 없이 걸리는 대로 싣기, 모델이 목록을 읽기(같은 말 알아보기, 모델 검사, 고칠 기억 고르기), 싣는 코드가 뜰 때마다 기억 파일을 모두 읽기, 낡음의 검사가 모든 기억을 훑기 |
| 기록의 길이 | 도구를 쓴 날의 수 | 쓰기는 한 줄을 덧붙이는 일이라 늘 같다. 되풀이를 세거나 실패를 모아 보는 자리가 기록을 처음부터 훑으면 날이 갈수록 붙는다 |

일의 몫은 싣는 때에 따라 모양이 다르다. 세션이 시작할 때 한 번 실으면 모델 요청 수에 정비례한다(5,000자를 요청 20번이 읽으면 10만 자). 말이나 도구 호출마다 실으면 글이 쌓여서 세션 길이의 제곱으로 붙는다(1,000자씩 20번이면 21만 자).

| 판단 | 근거 | 다시 열 조건 |
|---|---|---|
| 비용을 이 세 몫으로 나눠 본다 | 몫마다 줄이는 법이 다르다. 일이 길어지는 것은 피할 수 없어서 도구가 정하는 것은 곱해지는 크기뿐이고, 기억의 수와 기록의 길이에 붙는 몫은 구조로 끊을 수 있다 | 세 몫 어디에도 들지 않는 비용이 기준선이나 제품에서 재질 때 |
| 시간과 사용량을 따로 본다 | 시간은 일하는 길 위(싣는 자리, 도구를 부르기 직전의 검사)에서만 사람을 기다리게 한다. 사용량은 일하는 길 밖에서 돌아도 똑같이 든다 | — |
| 실린 글의 크기를 사용량과 따름에 함께 걸린 값으로 본다 | 실린 글이 클수록 다시 읽는 사용량이 늘고, 실린 지시가 많을수록 덜 따른다(IFScale) | — |

## 어림

아래는 셈이고, 실제로 잰 것이 아니다. 가상의 일 하나를 두고 선택지 여섯을 견줬다.

가상의 일은 세션 하나에 사람의 말 30번, 도구 호출 60번이어서 모델 요청이 약 90번이다. 기억은 200개, 기억 하나는 300자, 이 일에 걸리는 기억은 30개다. 단위는 처음 읽는 값으로 친 글자 수다.

| 선택지 | 다시 읽기, cache 없이 | 다시 읽기, 기준선의 cache 값으로 | 세션 끝에 차지한 자리 | 기억의 수에 붙나 | 일하는 길 위의 기다림 |
|---|---|---|---|---|---|
| 세션이 시작할 때 걸리는 기억 30개(9,000자)를 한 번 | 81만 | 10만 | 9,000자 | 아니다. 글 하나의 상한이 막는다 | 세션이 시작할 때 한 번 |
| 기준선(색인을 상한까지 채운 25,000자) | 225만 | 27만 | 25,000자 | 상한까지 | 없다 |
| 사람의 말마다 기억 셋(900자) | 126만 | 18만 | 27,000자 | 아니다 | 말마다 |
| 도구 호출마다 룰로 고른 힌트 300자 | 80만 | 11만 | 18,000자 | 아니다 | 호출마다 |
| 도구 호출마다 모델 검사(실린 9,000자와 명령) | 54만 | 6만과 출력 | 대화에는 없다 | 아니다 | 호출마다 모델의 응답 |
| 도구 호출마다 옆 모델이 기억 200개(60,000자)를 훑기 | 360만 | 43만과 출력 | 대화에는 없다 | 그렇다. 기억이 2,000개면 열 배다 | 호출마다 모델의 응답 |

cache의 값, 글 하나의 상한, 색인의 상한은 기준선의 값을 썼고, 그 값은 [Claude Code의 구조와 동작](../claude-code/structure.md)과 [원래 auto memory의 동작](../claude-code/auto-memory.md)에 있다. 옆에서 부르는 모델의 두 줄은 주 대화보다 짧게 남는 cache의 값으로 셈했다.

| 읽은 것 | 까닭 |
|---|---|
| 세션이 시작할 때 한 번 싣는 방식은 작고, 기억의 수와 떨어져 있다 | cache가 다시 읽기를 열 배쯤 싸게 하고, 글 하나의 상한이 크기를 막는다 |
| 가장 큰 것은 일의 몫과 기억 수의 몫이 만나는 자리다. 도구 호출마다 모델이 기억 전체를 훑는 방식이다 | cache를 셈해도 세션이 시작할 때 싣기의 네 배이고, 기억이 쌓이는 만큼 곱으로 는다. claude-mem의 issue(`#4965`)는 기억을 쓰는 옆 모델이 나흘 동안 245.5M token을 썼고 실제 작업은 348.4M token이었다고 적는다 |
| scope로 고르는 일은 끼어듦만이 아니라 상한이 강제한다 | 기억 200개는 본문(60,000자)도, 한 줄에 100자인 색인(20,000자)도 글 하나의 상한에 들지 않는다 |
| 기록의 길이는 코드가 훑는 한 문제가 되지 않는다 | 기록은 세션마다 백 줄쯤(실림 30, 검사 60, 전이 몇)이어서 석 달 뒤에도 수만 줄이다. 모델이 기록을 읽거나 일하는 길 위에서 훑을 때만 비용이 된다 |
| context 자리의 비용은 대화가 요약으로 바뀌는 때보다 따름 쪽에서 먼저 나올 수 있다 | 큰 창에서 수만 자는 요약을 거의 앞당기지 않는다. 실린 지시가 많을수록 덜 따르는 쪽(IFScale)이 먼저 걸린다 |

| 판단 | 근거 | 다시 열 조건 |
|---|---|---|
| 이 어림은 선택지의 크기 순서를 볼 때만 쓰고, 값 자체는 쓰지 않는다 | 가정이 모두 가상이다. 다만 가장 큰 줄은 둘째로 큰 줄의 1.6배이고, 기억의 수가 늘면 그 줄만 함께 커진다 | 실측이 어림과 크게 다를 때 |

## 줄이는 규칙

비용이 붙는 곳마다 줄이는 법을 정하고, 풀리는지 맞바꿈으로 남는지를 가렸다.

| 붙는 곳 | 줄이는 법 | 풀리나 | 남는 것 | 규칙이 적힌 곳 |
|---|---|---|---|---|
| 일: 말이나 도구 호출마다 싣는 글이 쌓인다 | 같은 세션에 이미 실린 기억은 다시 싣지 않고, 한 번에 싣는 수에 상한을 둔다 | 풀린다. 다시 싣는 글의 합이 걸리는 기억의 수에 묶인다 | 대화가 요약으로 바뀐 뒤에는 다시 싣는다 | [활용](using.md)의 실림과 내리기, 상한과 덜어내기 |
| 일: 이어 여는 세션마다 한 벌씩 더 실린다 | 떠나 있던 사이에 바뀐 기억만 싣는다 | 풀린다 | 없다 | [활용](using.md)의 실림과 내리기 |
| 일: 도구 호출마다 모델 검사를 기다린다 | 프로그램 검사를 먼저 하고, 모델 검사는 코드가 좁힌 호출에만 한다 | 줄지만 다 풀리지 않는다 | 좁히기가 놓친 호출은 검사되지 않고, 통과한 호출마다 기다림이 남는다 | 이 절 |
| 일: 세션 안에서 말을 뽑는다 | 말은 큐에 넣고 일하는 길 밖에서 처리한다 | 풀린다 | 처리가 끝나기 전에는 새 기억이 실리지 않는다 | [저장](storing.md)의 큐 |
| 기억의 수: 상한 없이 싣는다 | scope로 고르고, 상한을 넘으면 덜고 알린다 | 풀린다 | 덜린 기억이 닿지 않을 수 있다 | [활용](using.md)의 상한과 덜어내기 |
| 기억의 수: 모델이 기억의 목록을 읽는다 | 코드가 먼저 몇 개로 좁히고, 모델은 그 안에서만 고른다 | 풀린다. 모델의 입력이 기억의 수에 붙지 않는다 | 좁히기가 다른 말로 적힌 같은 주제를 놓칠 수 있다 | [저장](storing.md)의 뽑기 |
| 기억의 수: 싣는 코드가 뜰 때마다 기억 파일을 모두 읽는다 | 파일의 머리로 다시 짓는 색인 하나를 읽는다 | 풀린다 | 색인을 다시 짓는 코드가 하나 는다 | [저장](storing.md)의 한 곳과 내력 |
| 기억의 수: 낡음의 검사가 모든 기억을 훑는다 | 일하는 길 밖에서 돌리고, 바뀐 것만 본다 | 풀린다 | 없다 | 이 절 |
| 기록의 길이: 읽는 자리가 처음부터 훑는다 | 세는 값은 색인에 두고, 기록은 코드만 훑는다 | 풀린다 | 없다 | 이 절 |
| 시간: 싣는 코드가 자주 뜬다 | 제품이 쓰는 자리에만 걸고, 할 일이 없으면 바로 끝낸다 | 재기 전에는 가리지 못한다 | 한 번 뜨는 시간을 기준선을 돌릴 때 잰다 | 이 절 |

이 글에만 있는 규칙은 아래 다섯이다.

| 판단 | 근거 | 다시 열 조건 |
|---|---|---|
| 되풀이의 수와 실패의 수처럼 세는 값은 전이 때 색인에 함께 고친다. 기록은 덧붙는 원본으로 두고 코드만 훑으며, 모델은 큐에서 처리한 자리 뒤의 몫만 읽는다 | 읽는 자리가 기록을 처음부터 훑지 않아서, 읽는 비용이 기록의 길이에 붙지 않는다 | 색인의 값이 기록과 어긋나는 일이 생길 때 |
| 비용 때문에 기록의 수명을 두지 않는다. 수명은 읽기 쉬움이나 개인정보 같은 다른 까닭으로만 정한다 | 위 규칙으로 기록의 길이에 붙는 몫이 풀린다. 수명을 짧게 두면 [되찾기](using.md)를 잃는다 | 기록의 크기가 디스크나 훑는 시간에서 문제가 될 때 |
| 모든 기억을 훑는 낡음의 검사는 큐를 처리할 때 일하는 길 밖에서 하고, 근거 파일이 바뀐 기억과 기한이 지난 기억만 본다. 실을 때는 걸리는 기억만 대 본다 | 검사는 코드가 돌려서 모델을 부르지 않지만, 모든 기억을 훑으면 기억의 수에 붙는다 | 바뀐 파일을 알아내는 일이 검사보다 비쌀 때 |
| 검사를 두는 제품은 프로그램 검사를 먼저 한다. 모델 검사는 규칙이 없는 기억이 실려 있고 명령이 그 기억의 주제에 걸릴 때만 하고, 같은 기억과 같은 명령의 판정은 기록해 다시 쓴다 | 프로그램 검사는 모델을 부르지 않는다. 모델 검사는 호출마다 사용량과 기다림이 든다 | 좁히기가 놓친 호출에서 기억과 어긋난 명령이 지나가는 일이 시험에서 되풀이될 때 |
| 싣는 코드는 제품이 쓰는 자리에만 걸고, 할 일이 없으면 바로 끝낸다 | 싣는 코드는 자리마다 새로 뜬다. 가상의 일에서는 말 30번과 도구 호출의 앞뒤 120번을 더해 세션 하나에 150번쯤 뜬다 | 기준선을 돌릴 때 잰 시간이 일을 느리게 할 만큼 클 때 |

기억의 수와 기록의 길이에 붙는 몫은 모두 풀린다. 일의 몫은 없앨 수 없지만, 곱해지는 크기가 걸리는 기억의 수와 상한에 묶인다.

남는 맞바꿈은 둘이고, 둘 다 제품마다 달리 만들어 견주는 자리다. 상한과 덜어냄은 닿음과 맞바뀌고, 모델 검사의 사용량과 기다림은 따름과 맞바뀐다. 그래서 싣는 때와 도구를 부르기 직전에 할 일을 견줄 때 위 어림의 칸을 함께 적는다. 감당할 만한지는 기준선을 돌린 뒤 예산 값과 함께 정한다.

## 좁히기가 놓치는 자리

코드가 먼저 좁히는 자리에는 구조상 놓침이 있다. 세션이 시작할 때의 싣기는 찾지 않고 scope로 거르기만 해서, 상한 안이면 놓치지 않는다. 놓침은 찾기에 기대는 세 자리에서 생긴다.

| 자리 | 놓치면 | 받쳐 주는 것 | 재는 곳 |
|---|---|---|---|
| 상한을 넘어 덜린 기억을 뒤의 싣는 자리가 걸지 못한다 | 그 기억이 닿지 않는다 | 덜어 낸 것을 사람 화면에 알린다 | 닿음의 시험. 실을 목록으로 판정한다 |
| 뽑을 때 다른 말로 적힌 같은 주제를 알아보지 못한다 | 한 주제가 둘로 갈리고, 나중에 고칠 때 하나만 고쳐진다 | 주제의 다른 이름 | 고침의 시험 |
| 고칠 때 사람이 부르는 말로 기억을 찾지 못한다 | 낡은 값이 남는다 | 주제의 다른 이름 | 고침의 시험. 사람이 기억에 적힌 것과 다른 낱말로 부른다 |

놓친 뒤에는 [되찾기](using.md)가 받친다. 되찾을 때 사람이 쓴 낱말이 다른 이름으로 남아서, 같은 놓침이 되풀이되지 않는다.

## 재기

| 판단 | 근거 | 다시 열 조건 |
|---|---|---|
| 도구가 세션마다 쓴 것을 코드가 세어 기록에 남긴다. 실은 글자 수, 모델 호출 수와 token, 싣는 코드가 걸린 시간이다 | 구조에서 끌어낸 크기를 확인하려면 잰 값이 있어야 한다. 따로 장치를 두지 않고 기록의 줄을 읽는다 | — |
| 세션이 시작할 때 화면 한 줄로 요약해 보인다 | 기억 도구가 쓴 사용량과 차지한 자리는 사람에게 보여야 한다. 화면은 알리기만 한다 | 한 줄로는 어디서 비용이 드는지 가릴 수 없을 때 |
| 예산 값은 기준선과 제품을 돌려 본 뒤에 정한다 | 어림은 셈이어서, 감당할 만한지를 가를 값이 아직 없다 | — |

어림에서 재지 않고 둔 값과, 기준선을 돌려 잰 것이다. 잰 조건과 수치는 [원래 auto memory의 동작](../claude-code/auto-memory.md)의 다시 본 것 절에 있다.

| 무엇 | 어림에서 둔 값 | 기준선에서 잰 것 |
|---|---|---|
| 글자와 token의 비율 | 글자 수로만 셈했다 | 한글이 섞인 색인에서 token 하나가 1.6자를 조금 넘었다 |
