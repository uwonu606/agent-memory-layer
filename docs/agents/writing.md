# 글 쓰는 규칙

올라가는 문서(`README.md`, `GLOSSARY.md`, `docs/`, `tools/`의 README)를 쓰거나 고칠 때 지킨다. 고친 글이 아래 규칙 전부에 맞으면 끝난 것이다.

## 담는 것

| 규칙 | 까닭 |
|---|---|
| 판단은 판단, 근거, 다시 열 조건의 세 칸으로 적는다 | 근거가 바뀌면 판단을 다시 열 수 있어야 한다 |
| 지금 설계와 그 근거만 적는다. 판단이 바뀌면 새 판단으로 다시 쓰고, 바뀐 내력은 적지 않는다 | 내력은 지금 판단에 쓰이지 않으면서 읽는 양을 늘린다 |
| 다시 열 조건과 들어올 조건은 일어나는 일로 적는다. "견줄 때"처럼 우리가 마음먹는 때는 조건이 되지 못한다 | 그 일이 일어났는지를 가를 수 있어야 한다 |
| 조사한 글은 올리지 않고, 거기서 나온 판단과 근거를 올린다 | 조사 글은 낡고, 낡은 글은 지금 사실처럼 읽힌다 |
| 바깥 사례(다른 도구, 논문, issue)는 조사한 원문에 그렇게 적힌 것을 확인한 것만 적는다 | 확인하지 않은 수치가 판단의 근거로 굳는다 |
| 문서만으로 확인할 수 없는 것은 적지 않는다. 한 기기에만 있는 경로와 저장소에 없는 스크립트가 그렇다 | 읽는 사람이 따라가 볼 수 없다 |
| 대화에서 나온 말은 따옴표로 옮기지 않고 문서의 낱말로 풀어 적는다 | 문서의 낱말로 찾을 때 걸려야 한다 |

## 낱말과 예시

| 규칙 | 까닭 |
|---|---|
| 낱말은 `GLOSSARY.md`를 따른다. 새 낱말이 생기면 뜻, 영어 표현, 쓰지 않는 말과 함께 용어집에 먼저 올린다 | 한 개념을 한 이름으로 부른다 |
| 정의에는 harness의 이름을 넣지 않는다. 설계 글에서는 기준선이라고 부르고, Claude Code의 이름과 수치는 `docs/claude-code/`에 둔다 | 이 도구는 harness 하나에 묶이지 않는다 |
| 예시는 일반 예시로 쓴다. 저장소는 `todo-app`, 일의 갈래는 직장과 개인 프로젝트와 스터디, 기억은 "uv를 쓴다" 같은 것이다. 만든 사람의 회사나 저장소 이름은 넣지 않는다 | 설계와 시험이 한 사람의 사정에 맞춰지지 않게 한다 |
| 만들 도구 안의 개념(판, 기록)을 말할 때는 그것이 이 저장소의 문서가 아니라 도구 안의 것임을 처음에 밝힌다 | 옛 판이 문서의 옛 버전으로 읽힌 적이 있다 |
| 규칙으로 적은 문장은 예시 장면 하나로 풀어 본다 | 걸음마다 무엇이 정해져 있고 무엇이 비었는지가 드러난다 |

## 한 뜻은 한 곳에

| 적는 것 | 적는 곳 |
|---|---|
| 전이의 이름, 어디서 어디로 가는지, 계기 | `docs/design/state.md` |
| 전이마다의 규칙과 까닭 | `docs/design/storing.md`나 `docs/design/using.md`에 한 번 |
| 불변식 | `tools/state-check/README.md`의 표 |
| 제품 축, 뺀 것, 열어 둔 물음 | `docs/design.md`의 표 |
| 만드는 순서와 판단의 근거 | `docs/direction.md` |
| Claude Code에 묶인 사실 | `docs/claude-code/` |

## Claude Code 문서

`docs/claude-code/`의 글은 큰 구조와 기능만 적는다.

- 절마다 확인한 버전과 날짜, 문서로 읽었는지 실제 세션에서 돌렸는지를 적는다.
- 모르는 것은 어디까지 찾아봤는지를 적는다. 하지 않은 일은 적지 않는다. 적으면 다음 사람이 그 조사를 건너뛴다.
- 넘겨받은 값은 옮기기 전에 공식 문서 원문에 문장마다 대 본다.
- Claude Code가 바뀌면 그 글의 "다시 조사할 때"에 적힌 절만 공식 문서와 실제 세션으로 새로 본다.
- 실험 스크립트는 저장소에 두지 않는다.
