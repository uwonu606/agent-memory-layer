# agent-memory-layer — constraint one-pager

2026-11-26. 얹는 제품을 다섯째 장치까지 돌린 뒤 실제로 지켜진 제약을 적는다. 새 요구는 받기 전에 이 글의 defining constraint, 방향, 변경 규칙, tripwire에 대 보고, 정한 판정을 gate 기록에 한 줄 남긴다.

낱말은 [용어집](../../GLOSSARY.md)을 따른다. 아래에서 `overlay`는 [얹는 제품](../../products/overlay/README.md), `design`은 [설계의 입구](../design.md), `direction`은 [판단과 방향](../direction.md), `auto-memory`는 [원래 auto memory의 동작](../claude-code/auto-memory.md)을 가리킨다.

## defining constraint

기억에 일어난 일(실림, 바뀜, 쓴 양)은 묻지 않아도 사람이 읽는 한 줄로 남는다.

| 칸 | 내용 |
|---|---|
| 보는 곳 | 세션의 첫 화면 줄, 답 끝의 줄, 기록 폴더의 기억마다의 내력과 세션마다의 쓴 양(`overlay`의 사람 화면, 기록 폴더의 모양) |
| 쳐내는 것 | 줄을 남기지 않는 동작(말없는 배경 정리, 모델에게만 가는 경고, 옆 모델의 조용한 고침, 요약해서 싣기), 사람을 세우는 승인, 사람이 바로 읽을 수 없는 곳에만 있는 사실 |
| 출처 | 아래 본질의 앞 셋과 견주기, 기록. 기준선에서 사람이 읽어서 알 수 없던 것(`auto-memory`의 사람에게 보이지 않는 것)이 둘째와 다섯째 장치에서 줄로 떴다 |

## 본질

제약마다 그것이 낳은 성질과, 구조가 바뀌는 동안 지켜졌는지를 적는다. 살아남음은 시험받고도 지켜진 것이고, 부딪힘은 예외가 생긴 것이다.

| 제약 | 낳은 성질 | 판정 | 근거 |
|---|---|---|---|
| 세션에 실린 기억은 묻지 않아도 사람 화면에 보인다 | 사람이 이번 세션의 재료를 안다 | 살아남음 | `overlay`의 둘째 장치가 푸는 것. 사람이 읽어서 아는지는 판정하지 않았다 |
| 기억이 바뀌면 그 답 끝에 알리고, 판으로 되돌릴 수 있다 | 묻지 않고 고치게 두어도 틀린 것을 바로잡는다 | 살아남음 | `design`의 당기는 짝. 막는 장치는 `design`의 뺀 것에 있다 |
| 도구는 사람을 기다리게 하지 않는다. 화면은 알리기만 하고, 실패해도 일은 이어진다 | 일의 속도가 기준선과 같다 | 살아남음 | `direction`의 방식을 거르는 기준, `overlay`의 사람 화면 |
| 기억의 원본은 사람이 읽는 markdown 파일이다 | 사람, 모델, hook이 같은 원본을 읽는다 | 살아남음 | 기준선의 기억 파일을 그대로 쓴다(`auto-memory`) |
| 바뀜은 기억 폴더의 상태를 기록의 마지막 판과 견주어 잡는다 | 모델이 어떤 길로 바꿔도 내력이 빠지지 않는다 | 살아남음 | `design`의 뼈대 |
| 기록은 기억 폴더 밖에 덧붙이기만 하는 원본으로 두고, 풀이는 원본에서 다시 짓는다 | 옛 판이 지금 값으로 읽히지 않고, 되돌릴 수 있다 | 살아남음 | `design`의 뼈대, `overlay`의 기록 폴더의 모양 |
| 도구는 기억을 쓰지 않는다. 쓰고 싣고 고치는 일은 기준선이 한다 | 기준선이 잘하는 것을 잃지 않고, 도구를 떼어도 기억은 그대로다 | 살아남음 | `design`의 뼈대. 예외는 사람이 부르는 되돌리는 명령이다 |
| 장치는 인자 하나로 켜고 끄며, 끄면 출력과 기록이 글자까지 같다 | 어느 장치가 무엇을 바꿨는지 보인다 | 살아남음 | `overlay`의 판단, 확인한 것 |
| 도구는 상주 process 없이 hook 스크립트로 돈다 | 죽을 process가 없고, 떼는 일이 설정 두 칸이다 | 살아남음 | `overlay`의 붙이는 법. 세션이 시작할 때의 hook이 시간 예산을 넘는다(`design`의 예산) |
| 보이려는 글은 사람 화면에만 내고, 모델에게 가야 하는 글은 사실로 적는다 | 보이는 일이 숨은 비용을 늘리지 않는다 | 살아남음 | `design`의 당기는 짝, `overlay`의 판단 |
| 테스트셋과 기준선이 제품보다 먼저다 | 예상이 틀렸음을 만들기 전에 안다 | 살아남음 | `direction`의 순서 |
| 기준선이 통과한 일은 만들지 않는다 | 도구가 모든 것을 처리하려 들지 않는다 | 살아남음 | `design`의 뼈대, 뺀 것의 앞 여덟 줄 |
| 찾는 일은 코드가 하고, 같은 사실인지 가리는 일은 모델이 한다 | 놓친 기억을 찾는 일이 모델의 검색어에 달리지 않는다 | 부딪힘 | 고침에서는 지켜졌다(`direction`의 제품의 차례). 읽기에서는 기준선의 모델이 잘린 기억을 스스로 찾았다(`design`의 뺀 것) |
| scope는 기억마다 적힌 표시가 정한다 | 한 자리에 모으고도 한 곳에만 준 말이 끼어들지 않는다 | 부딪힘 | 같은 폴더에서 연 다른 일에서 아홉 번 가운데 한 번 그 폴더의 규정을 따랐다(`design`의 뺀 것). 표시는 모델이 따를 때만 듣는다 |
| 사람이 정한 기억은 사람의 말로만 바뀐다 | 정해 둔 것이 모르는 사이에 바뀌지 않는다 | 부딪힘 | 얹는 제품은 기억의 쓰기를 막지 않는다. 기준선은 그런 기억을 건드리지 않고 물었다(`design`의 뺀 것) |
| 통과와 실패로만 가른다 | 판정이 또렷하다 | 부딪힘 | 넷째 장치는 정해진 판정이 실패인 채로 넣었다(`direction`의 제품의 차례) |

부딪힌 제약마다 정한 것이다.

| 제약 | 정한 것 |
|---|---|
| 찾는 일은 코드가 한다 | 고침에서 지킨다. 읽기는 기준선에 둔다 |
| scope는 표시가 정한다 | 지킨다. 일의 갈래는 들어올 조건이 드러날 때까지 넣지 않는다 |
| 사람이 정한 기억은 사람의 말로만 바뀐다 | 놓는다. 바뀌면 알리고 되돌린다는 쪽을 본질로 둔다 |
| 통과와 실패로만 가른다 | 제품을 견줄 때는 지킨다. 장치를 넣을지는 겨눈 자리에서 한 일로 가린다 |

## 우연으로 내린 것

지켜지던 때가 있었지만 낳은 성질이 없거나 다른 길로 얻은 것이다. 다시 들이지 않는다.

| 제약 | 이유 |
|---|---|
| 범위는 기억이 놓인 폴더가 정한다 | 기준선의 저장소별 폴더를 따른 모양이고, 그 모양에서는 다른 저장소에서 남긴 기억이 닿지 않는다(`auto-memory`) |
| 기준선을 끄고 쓰는 일까지 직접 만든다 | 기준선이 기억을 쓰는 쪽의 시험 열하나 가운데 아홉을 통과했다(`design`의 뼈대) |
| 기억의 바뀜을 도구 호출 뒤의 hook으로 잡는다 | 기준선의 모델이 shell 명령으로도 기억을 바꾼다(`design`의 뼈대) |
| 늘 싣는 글의 한도는 10,000자다 | hook이 넣는 글로 싣던 때의 harness 한계다. 얹으면 기준선의 색인 상한을 따른다(`design`의 예산) |

## 변경 규칙

이 프로젝트가 구조를 바꿀 때 지켜 온 규칙이고, 끝의 둘은 선례에서 빌렸다.

| 규칙 | 출처 |
|---|---|
| 뺀 것은 들어올 조건과 함께 적는다 | `design`의 뺀 것 |
| 막기 전에 기록하고 알린다 | `design`의 당기는 짝 |
| 물음을 대화로 닫지 않고 만들어 돌려서 가린다 | `direction`의 첫 원칙 |
| 기준선을 먼저 돌리고, 기준선이 통과한 일은 만들지 않는다 | `design`의 뼈대 |
| 장치는 하나씩 얹고, 인자로 켜고 끄며, 끄면 글자까지 같게 둔다 | `overlay`의 판단 |
| 시험의 판정은 지표다. run을 읽어 확정하고, 장치는 겨눈 자리에서 한 일로 가린다 | `direction`의 제품의 차례 |
| 원칙은 제약으로 굳히기 전에 그 원칙이 풀려는 문제를 먼저 적는다 | `direction`의 방식을 거르는 기준 |
| 실제 home에 놓기 전에 격리된 home에서 먼저 돌린다 | [README](../../README.md)의 만드는 방식 |
| 같은 상태는 한 번만 알리고, 상태가 바뀌거나 풀릴 때만 다시 알린다 | Letta의 기억 알림이 바뀌지 않은 상태를 답마다 다시 알린다는 보고와 그 제안("Deliver the remaining reminders once per repository state", `letta-ai/letta-code#4830`, 2026-11-26에 읽음. 제안이고 들어가지 않았다) |
| 받는 쪽이 손쓸 수 없는 상태는 그쪽에 알리지 않는다 | 같은 보고("Two of the eight memory reminders describe states the agent cannot act on") |

## tripwire

| 무엇을 보면 | 무엇을 다시 여나 |
|---|---|
| 같은 줄이 바뀐 것 없이 되풀이되거나, 사람이 손쓸 수 없는 일을 알리는 줄이 생긴다 | 화면에 줄을 내는 때 |
| 줄이 떴는데도 사람이 바뀐 것을 모른 채 일한다 | 한 줄로 알린다는 방식 |
| 색인이 상한을 넘어 잘린 기억 때문에 틀린 답이 난다 | 폴더 하나에 모으는 것과, 싣기를 기준선에 맡긴 것 |
| scope 표시를 모델이 따르지 않아 다른 저장소에 준 말대로 한다 | 표시를 모델이 따르게 둔 것. 코드가 거르는 쪽을 연다 |
| 기억을 쓰는 일을 도구가 가져와야만 풀리는 실패가 시험에서 드러난다 | 도구는 기억을 쓰지 않는다 |
| 기준선의 기억 기능이 바뀌어 기억 폴더의 모양이나 싣는 방식이 달라진다 | 견주기와 실린 글을 세는 법 |
| hook이 읽는 양을 줄인 뒤에도 세션이 시작할 때의 hook이 시간 예산을 넘는다 | 상주 process 없는 hook 스크립트. 다시 지을 수 있는 색인으로서의 DB를 연다 |
| 값이 없는 고침에서, 링크로 이어진 기억을 기준선이 놓친다 | 고칠 기억을 찾는 열쇠. 링크를 따라가 알리는 장치를 연다 |

## gate 기록

날짜, 요구, 판정, 근거의 순서로 한 줄씩 적는다. 제약을 다시 정하는 일은 사용자가 `/constrain`으로 한다.

- 2026-11-26 고칠 때 기억 사이의 관계를 그래프로 따라가기 → 시험부터 더한다. 관계를 따로 저장하지 않고 기억 파일에 있는 링크를 읽는 쪽으로 보고, 기준선이 실패할 때만 장치를 얹는다 — 찾는 일은 코드가 한다는 본질에 들어오지만, 따로 둔 관계는 줄 없이 낡는다
- 2026-11-27 SQLite나 PostgreSQL 같은 외부 DB 쓰기 → 아직 들이지 않는다. 들일 때는 기록에서 다시 지을 수 있는 색인으로 SQLite를 먼저 본다 — 기억의 원본은 기준선이 쓰는 markdown 파일이고, DB에만 있는 사실은 사람이 바로 읽을 수 없다. 세션이 시작할 때의 hook이 시간 예산을 넘는 것은 읽는 양을 줄이는 일이 먼저다. PostgreSQL은 상주 process가 따라온다
